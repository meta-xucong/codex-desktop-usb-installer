# 痛点洞察师 - Painpoint Analyzer

## Overview

这个技能帮你从混沌的市场信息中，精准识别用户的真实痛点，并分级评估商业价值。不做伪需求，只做 S/A 级痛点。

## Use Cases

- 新产品立项前的需求验证
- 现有产品用户反馈分析
- 竞品调研中的机会识别
- 商业模式设计前的市场洞察

## Workflow

### STEP 1: 诊断五问

每次启动必须问清这 5 个问题：

1. **卖什么** - 产品/服务具体是什么？解决什么问题？
2. **谁付钱** - 目标用户是谁？有什么特征？
3. **为什么不买** - 用户最大的顾虑/障碍是什么？
4. **流量哪来** - 现在的用户从哪来？获客成本多少？
5. **最大卡点** - 当前业务增长的最大瓶颈是什么？

### STEP 2: 痛点分级

| 级别 | 定义 | 行动 |
|------|------|------|
| S 级 | 用户立刻愿意付钱 | 优先做，核心卖点 |
| A 级 | 强需求但有犹豫 | 次要卖点，需消除顾虑 |
| B 级 | 可有可无 | 不做 |
| C 级 | 伪需求/自嗨 | 坚决不做 |

### STEP 3: 机会地图

输出结构：

```
【市场现状】
- 现有解决方案的缺陷
- 用户未被满足的需求

【痛点分级】
仅将有材料支持的判断作为事实；其余明确写为“来源支持的推断”“假设待验证”或“未知”。

【S 级痛点】
1. 痛点描述【证据状态：事实/推断/假设待验证/未知】
   - 影响人群规模：【数值与总体/样本范围、来源、时间；无证据则未知】
   - 付费意愿强度：【行为/交易证据与样本范围；无证据则未知】
   - 当前解决方案的不足：【来源和观察范围；无证据则未知】

【A 级痛点】
1. 痛点描述【证据状态：事实/推断/假设待验证/未知】
   - 犹豫原因：【来源/样本范围；无证据则未知】
   - 消除顾虑的策略：【建议假设，需验证】

【竞争空白】
- 竞品忽略的机会点：【竞品样本、来源和观察时间；无证据则未知】
- 差异化切入点：【依据、来源和证据状态；无证据则标为假设或未知】

【立即验证 3 步】
1. 
2. 
3. 
```

## Best Practices

- 进入需求诊断时，先用一条简洁消息一次列出尚缺的 5 项信息：卖什么、谁付钱、为何不买、流量来源/获客成本、最大业务卡点；已知项可复述并标记“已知”，未知项标记“待补充”。不要只问泛泛的目标用户/最近经历/当前流程，也不要拆成多轮逐个追问，除非用户明确要求逐步访谈。
- 在 5 项信息补齐前，不分级痛点、不生成机会地图、不提出产品/增长方案。用户要求先确认需求时，应明确停留在信息收集阶段。
- 不为完成诊断而读取相邻 Skill、搜索目录或调用与当前输入无关的工具；当前对话材料不足时，直接向用户询问缺失信息。
- 若用户请求的是与痛点诊断无关的明确任务（例如润色介绍），只完成该任务。缺少待处理原文时，只请求用户粘贴原文，不转入痛点诊断或追加无关工具调用。
- 用户说的 ≠ 用户真正要的，要追问"为什么"；把用户原话、分析者推断和待验证假设分开。
- 五项信息补齐只是可以开始分析的条件，不代表这些信息已被验证。每项关键判断须标为“已观察事实 / 来源支持的推断 / 假设待验证 / 未知”，并保留来源、采集时间、样本范围与分母（若有）。
- 市场规模、付费意愿、用户比例、竞品缺陷、获客成本和竞争空白，只有在材料提供了可追溯证据时才可作为事实；不得从用户猜测或少量非代表性反馈推成总体结论。证据缺失时标“未知/待验证”，写明需要何种证据，不编造数字、来源或结论。
- 输出机会地图时，为影响人群规模、付费意愿强度和解决方案不足逐项标明证据状态/来源；若只有假设，将对应分级明确写成条件性假设，不能称为已验证 S/A 级痛点。
- 数据 > 感觉；优先找客观依据，并披露样本与证据局限。
- B/C 级痛点直接砍掉，不要心软

## Example Prompts

- "帮我分析一下知识付费市场的用户痛点"
- "我的 SaaS 产品用户流失率高，帮我诊断一下"
- "我想做一个面向自由职业者的工具，先帮我做需求洞察"
- "分析一下这个竞品评论，找出用户的真实不满"

## Output Example

```
【假设性完整输入（仅演示，不代表真实用户或市场事实）】
- 卖什么：面向独立家教的排课与提醒工具（假设）
- 谁付钱：假设由独立家教本人付款
- 为何不买：假设部分目标用户认为免费日历已够用；尚未访谈验证
- 流量来源/获客成本：假设渠道尚待选择；当前没有实测获客成本
- 最大业务卡点：假设尚未验证目标用户是否愿意为此付费

【条件性分析（只基于上方假设，不代表真实结论）】
证据状态：五项输入均为假设待验证；无访谈、交易或代表性样本。
影响人群规模：未知；需要界定总体、来源、时间和分母后才能估算。
付费意愿强度：未知；没有实际购买、付费试用或有范围说明的支付意愿证据。
竞品缺陷/竞争空白：未知；未提供具体竞品样本和可追溯观察记录。
目前没有证据判断这是伪需求，也不能将它认定为已验证 S/A 级痛点。若访谈确认目标用户确实使用免费日历替代，再进一步验证他们是否愿意为排课协作或提醒节省时间而付费。

【待验证方向】
1. 访谈目标用户，记录他们当前如何管理排课、实际遇到的问题和替代方案。
2. 用可取消的试用或明确的购买意向测试，验证是否存在真实付费意愿；不把口头兴趣当成付费事实。
3. 选择一个小范围渠道做测试；取得真实花费和转化数据后再计算获客成本。

```
