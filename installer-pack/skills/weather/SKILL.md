# 天气查询

纯气象原理解释，或用户明确要求不查实时天气时，不调用天气服务。需要查询实时天气时，优先使用对话中已明确且无歧义的地点，不重复追问；地点缺失或同名地点无法消歧时，先询问国家/地区或行政区，不能自行猜测。回复时回显来源解析出的城市、行政区/国家；若来源地点与用户指定不一致或来源无法确认地点，停止给出该地天气并说明原因。时间按该地点当地时区表达；无法可靠确定时区则明确标注未知，不把查询者时区当作地点时区。

当前天气是实时信息，必须写明带时区的查询时间和数据来源；优先使用当前 Codex 提供的原生天气或网页能力。涉及预警、航空、海事或官方决策时，改查当地官方气象服务并明确其发布时间。

区分“实况观测”和“预报”：分别标注来源、观测时间或预报有效时段，以及查询时间；每个可用时间都要带地点时区或明确的 IANA 时区。来源没有提供地点、时区、观测时间/有效时段等回答所需字段时，不自行补全或推断：改用能够提供这些字段的来源，否则说明该字段无法核验，并降低结论范围。空响应、超时、非成功 HTTP、无效结构/JSON、地点不匹配、缺少必要时间字段或数据明显过期，都按“当前数据不可核验”处理，不包装成实时天气。若来源对温度、降雨或更新时间有明显冲突，保留各自来源与时间并说明冲突，不能择一包装成确定结论或将观测与预报拼接。

引用来源若在 URL 中带有日期筛选参数（例如 `month`、`year` 或具体日期），必须确认参数指向所述天气的当地日期/时段；参数不匹配时，该页面不能支持该日结论。改用日期匹配的来源，或明确说明该日信息无法核验。

原生能力不可用、但当前执行环境明确允许外网请求时，Windows 才使用系统自带的 `curl.exe` 作为回退；回退输出必须通过上述地点、时区、新鲜度和字段检查。简写响应如 `format=3` 仅当实际响应字段足以支持所写结论时才可引用；没有地点或时间元数据时，不用于当前实况/预报报告，改用结构化响应或说明无法核验：

```powershell
curl.exe "https://wttr.in/London?format=3"
curl.exe "https://wttr.in/London?format=j1"
```

也可以使用 PowerShell 回退：

```powershell
Invoke-RestMethod "https://wttr.in/Beijing?format=j1"
```

所有回退都失败时，说明无法实时核验，不根据季节或常识猜天气。本技能不保存用户位置或查询历史。若需要记忆
城市，请由用户明确指定一个项目内的存储文件。
