# 可复盘改进

把一次任务中的有效经验整理成短小、可验证的 Markdown 记录，帮助后续任务减少重复错误。
本技能只使用工作区文件，不修改全局 `AGENTS.md`，不安装钩子，也不读取会话数据库或隐私记录。

## 什么时候记录

- 命令或操作异常失败：记录现象、原因、修复和验证方式。
- 用户纠正了结论：记录原判断、正确判断和以后如何避免。
- 发现缺失能力：记录需求、影响和可接受的临时方案。
- 外部服务失败或返回异常：记录服务、时间、请求类别和脱敏后的错误。
- 形成可复用的更好流程：记录适用条件、步骤和停止条件。

## 文件布局

在当前项目根目录创建 `codex-learnings/`，按需维护：

```text
codex-learnings/
  LEARNINGS.md
  ERRORS.md
  FEATURE_REQUESTS.md
```

文件只保存脱敏后的事实，不写入 API Key、Cookie、访问令牌、个人通信内容、会话原文或生成文件。
如果项目已经有自己的知识库，优先沿用项目约定；不要新建第二套全局记忆目录。

## 记录模板

```markdown
## YYYY-MM-DD — 简短标题
- 类型：correction | error | feature | workflow
- 触发：发生了什么
- 结论：以后应采用什么判断或做法
- 验证：如何证明已经修正
- 适用范围：项目、平台或依赖版本
```

## 使用规则

1. 先检查当前项目的 `codex-learnings/`，再开始高风险或重复性任务。
2. 只记录能够改变后续决策的内容，避免把普通聊天变成日志。
3. 需要把经验提升为项目规范时，先征得用户同意，再修改项目内的说明文件。
4. 不因为记录了经验就声称系统已经自动学习；每次复盘都必须有可见文件或验证证据。
