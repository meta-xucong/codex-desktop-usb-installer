# Offer 设计师 - Offer Designer

## Overview

把产品从"功能清单"升级为" irresistible offer（无法拒绝的提案）"。解决"卖什么、怎么卖、卖多少钱"的核心问题。

## Use Cases

- 新产品定价与包装
- 现有产品重新定位
- 设计高转化销售页面
- 构建产品矩阵与 upsell 路径
- 仅询问定价概念/术语且未要求具体 Offer 时，直接解释概念，不套用 Offer 输出模板。

## Workflow

### STEP 1: 价值锚定

明确 3 个核心问题：

1. **结果价值** - 用户购买后能得到什么具体结果？
2. **情感价值** - 用户购买后感觉如何？（身份认同、安全感、成就感）
3. **社会价值** - 用户购买后在他人眼中如何？

### STEP 2: Offer 结构设计

Offer 以核心产品为基础；赠品、风险逆转和稀缺性都是**可选组件**，只有与商家真实交付、退款条款或可核验容量/期限相符时才使用。证据不足时省略，或标为“待商家确认”的草案。

| 组件 | 说明 | 示例 |
|------|------|------|
| 核心产品 | 解决核心痛点的主体 | 课程、工具、服务 |
| 超级赠品（可选） | 增加实际交付价值；先确认资源、成本和履约能力 | 仅列已存在或明确规划的模板库、社群、1v1 |
| 风险逆转（可选） | 降低购买顾虑；必须符合已确认的退款条款和履约能力 | 仅使用商家确认的退款或试用条款 |
| 稀缺性（可选） | 仅在有真实容量、库存或截止条件时说明 | 仅使用可核验的名额、库存、期限或价格变化 |

### STEP 3: 定价策略

三种定价模型：

**成本加成定价（Markup）**
- 成本加成率 = (售价 - 成本) / 成本；售价 = 成本 × (1 + 成本加成率)。
- 这不是目标毛利率公式。若目标是毛利率，毛利率 = (售价 - 成本) / 售价；售价 = 成本 / (1 - 目标毛利率)，目标毛利率必须小于 100%。
- 纯算术示例：成本为 100，20% 成本加成得到售价 120（对应毛利率约 16.7%）；目标毛利率 20% 则售价为 125。示例只解释公式，不是市场价格建议。
- 局限：单独使用时可能无法反映用户感知价值

**价值定价法**
- 基于用户获得的价值定价
- 可将“用户获得价值 × 10%~30%”作为待验证的情景假设之一，不是通用定价公式或行业事实；应结合支付意愿、成本、竞品和获客/服务成本给出范围并说明依据。

**竞争定价法**（参考）
- 对标竞品，略高或略低
- 必须有明确的差异化支撑

## Best Practices

- 结合用户价值、成本和替代方案选择定价方法，不把任何一种方法说成普遍最优
- 赠品应有可交付价值，并核对实际成本与履约能力
- 风险逆转要真实可信，不要假承诺
- 稀缺性必须是真实的，否则就是欺骗

### 数据、承诺与发布边界

- 不得编造用户成果、市场数据、转化率、ROI、客户案例、评价、原价/折扣、退款政策、剩余名额或截止时间。只有用户提供了可核验依据时，才把这些写成事实。
- 缺少验证依据时，将价格、价值、销量或促销条件标成“建议假设/待验证”，并提供需要补齐的数据；不得把虚构稀缺性或保证收益当作默认 Offer 组件。
- “风险逆转”和“超级赠品”必须与商家的实际交付、退款条款、成本及履约能力一致。未确认前只能给可选草案，不应写成已经存在的承诺。
- 定价建议至少区分成本底线、目标用户支付意愿、替代方案/竞品、服务成本和测试计划；没有数据时说明置信度有限，不把单一比例公式当作结论。
