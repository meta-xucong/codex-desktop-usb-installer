# Grok Prompt Compiler 设计文档

## 目标

把“自然语言视频需求”变成可解释、可测试、可复用的生成计划：

```text
自然语言 + 参考图
  -> Codex 提取 SceneSpec
  -> compiler 校验与风险审计
  -> Grok effective strategy
  -> Prompt + negative prompt + QA checklist
  -> provider profile / capability / payload-contract check
  -> reference URL preparation (only for explicit I2V generation)
  -> aiself-video MCP
  -> 轮询、下载、抽帧验收
```

核心原则：创意层和模型适配层分离；原始要求不丢失；降级必须可见；代码只做确定性工作。

## 组件

### 1. SceneSpec

模型无关的中间表示，保存用户要求的事实，不保存某个模型的措辞。字段契约见 `scenespec.md`。

### 2. Risk auditor

根据可观察字段打分：

| 规则 | 分值 | 结论 |
| --- | ---: | --- |
| 拼贴/贴纸/多人物参考图 | 30 | 检查参考元素是否是目标画面；只有不需要时才准备清洁版本 |
| `reference.usage=identity_only` 且接口没有角色分离 | 25 | 按本次任务选择身份参考替代方案 |
| 当前 host/profile/model 没有已确认的参考图输入契约 | 30 | 提交前阻断，先确认字段、模式和限制 |
| 历史实测与当前上游图像输入错误冲突 | 30 | 视为 provider capability drift，停止自动重试 |
| 画面输入源图比例与目标比例不一致 | 10 | 针对本次画面输入做目标比例重构，禁止非等比缩放 |
| 本次任务要求全身但画面输入是半身/近景 | 10 | 准备符合本次机位的全身输入 |
| requested transition 是飞入、分身或贴纸融合 | 25 | 报告不稳定风险，并提供拆镜头、遮罩或原地变化候选 |
| 3 次以上换装 | 15 | 时间和身份漂移风险 |
| 4 次以上换装 | 10 | 建议分段或后期剪辑 |
| 精确 beat sync + 音乐生成 | 15 | 重拍需后期验证 |
| 明确要求固定镜头或全身构图且输入不匹配 | 10 | 针对本次镜头报告构图漂移风险 |
| 多个场景或多个演员且要求连续稳定互动 | 15 | 报告连续性风险，保留剧情要求并提供分镜拆分候选 |
| 明确要求复杂舞蹈/连续物理 | 10 | 动作只能近似执行 |
| 连续性锚点在相邻镜头交接状态不一致 | 20 | 在生成前修正目标首帧或显式声明变化 |
| 两个以上可见锚点抢占同一肢体/空间槽位 | 10-20 | 重排构图或显式说明共享关系，避免模型自行换手/丢道具 |
| 一个短镜头维持五个以上连续性锚点 | 10 | 保留复杂画面，但只把真正不可丢失的关系升为 `critical` |
| 已拒绝的来源帧仍作为直接图片输入 | 35 | 视为来源污染；从生图/I2V 输入排除，只保留文字状态 |

分级：0-24 `low`，25-49 `medium`，50-74 `high`，75+ `critical`。分值只是风险沟通，不是成功概率。

### 3. Strategy downgrader

降级是策略替换，不是删除原始需求：

- `identity_only` 且没有独立身份参考通道 -> 提供 `reference_strategy` 候选，不自动覆盖用户画面方案
- provider 契约未知、或当前响应与历史成功契约冲突 -> 阻断创建任务，保留证据并要求先重新认证；不得换字段盲试
- 画面输入中的 `collage`、`stickers` 或多主体与目标画面不一致 -> 提供清洁输入候选，不自动删除剧情元素
- 源图比例不等于目标比例，且该源图参与画面输入 -> 提供 `target_ratio_final_scene_frame` 候选
- `full_body_cutout_fly_in`、`sticker_merge`、`clone_fusion` -> 提供 `in_place_beat_change` 候选，只有本次任务选择降级时才写入有效 Prompt
- `outfit_changes >= 3` -> 提供 `sync_strategy=approximate_then_qa` 候选
- `beat_sync=true` 且 `audio.generate=true` -> 提供 `audio_strategy=generate_then_verify_or_replace` 候选
- `scene_count > 1` -> 提供分镜拆段候选，不自动改为单场景
- 声明 `continuity` -> 审计状态交接、接触槽位和允许变化；它只针对声明的关系工作，不自动减少演员、道具、场景或镜头运动
- 声明 `reference.input_ledger` -> 审计来源素材资格；`rejected + direct_input` 阻断创建任务，`text_summary` 允许继承剧情而不继承错误像素
- 声明 `pacing.mode=real_time` -> 审计时间节拍、剧情推进和慢动作冲突；不对慢镜、舞蹈、氛围或展示镜头默认启用

### 4. Prompt compiler

使用固定顺序：主体和身份（若有） -> 场景 -> 镜头 -> 时长画幅 -> 换装策略 -> 时间轴 -> 音频 -> 负面约束。模板保持短小；默认 4096 UTF-8 bytes 是用于发现重复提示的软预算，超出只产生建议，不得截断或阻断任务。只有当前 provider profile 通过官方文档、网关响应或受控实测证实的 `provider.max_prompt_bytes` 才是硬门槛。未在 SceneSpec 中明确的主体数量、机位、镜头运动、画面排除项不得由模板补入。

### 5. Continuity auditor

连续性不是“画面里只能一个人”的替代词。它是一份按镜头使用的状态图：哪些人、道具、走位、服装、视线或环境关系必须维持，哪些关系允许在本镜中明确变化，哪些细节只作为氛围存在。

对每个 `critical` 锚点，先验收首帧是否呈现正确状态，再验收叙事转折和结尾。相邻镜头把已验收的结尾状态写进下一镜 `handoff_from`。若交接不一致，先改目标首帧或声明一次状态变化；不要重复提交同一 Prompt。

物理关系应以可见接触点或相对位置表达，例如：提手套在前臂、道具由哪只手持有、人物位于谁的画面左侧。模型未必严格模拟物理，但明确的关系图能防止它在多道具、多演员场景中无意换手、换侧或删去连接物。

运动动词也需要几何关系。对“进入、离开、靠近、交接、追逐”这类镜头，设置独立的空间/路径锚点，写明角色相对镜头、门、柜台或另一角色的起点、朝向、终点和允许变化。首帧必须已经显示正确的镜头一侧和身体朝向，否则“走向出口”仍可能被模型演成朝店内或镜头走来。

道具关系和人体完整性要分开声明。包被前臂承载并不保证该侧手掌、手指或整条手臂在画面中没有被包遮住；当这些解剖点对剧情或道具可信度重要时，把它们作为独立锚点验收。反之，镜头本来就允许遮挡或裁切时，不应为了通用规则强行要求双手可见。

位置锚点不能表示物体数量守恒。对唯一且会移动的关键实体，额外使用 `continuity.inventory` 声明物理实例数、起止状态、唯一的转移序列和任务特有的禁止状态。编译器据此同时产生正向约束、负面约束和转移点 QA，例如一盒牛奶从柜台到右手后不可复制到左手、不可继续留在柜台、不可变成手机。该账本是选择性的：它允许服务员与顾客之间的一件物品交接，也允许复杂场景保留多个演员；只是不允许已声明为唯一的实体被模型任意增删或重排。

守恒约束不是物理引擎。高风险转移仍要在起始、转移中和结尾检查数量、接触点和旧位置清空状态。若模型持续失败，优先将交接拆成前后两镜或准备更接近转移前状态的画面输入，而不是把所有道具都锁死或无限追加负面提示。

该机制保留复杂画面的能力：群舞可锚定队形变化，餐厅戏可锚定主客相对位置，动作戏可锚定关键物体的交接，镜头运动和多人物仍由任务本身决定。仅把真正影响叙事的关系标为 `critical`，避免把全部布景塞进 Prompt。

### 6. Source qualification auditor

参考图的“身份用途”和“能否作为像素输入”是两件事。一个上一镜结尾帧可能仍然提供可用剧情事实，却因包带、人物手位、服装、构图或角色数量错误而不具备视觉复用资格。因此每个候选素材进入 `input_ledger`：

- `approved + direct_input`：已按本镜关键锚点验收，可参加生图首帧合成或 I2V。
- `rejected + excluded`：禁止把文件传入任何后续图像或视频调用。
- `approved + text_summary`：只保留文字状态，例如“付款已完成，角色正走向出口”，不传文件像素。

该闸门不决定素材数量或场景复杂度。它只阻止已知错误的像素通过多图编辑回流，避免“模型参考上一镜”成为不断放大错误的链路。

### 7. Narrative pacing auditor

视频总时长不是一个动作可自由填充的容器。实时剧情片应把时长拆成至少两个可见状态变化，并在需要时声明一个可辨认的转折：例如走向门口、回头回应、完成一次确认后离开。编译器把这些写成带时间点的 Prompt 和验收项目，同时明确禁止慢动作、时间拉伸、静止等待和无目的停留。

这不是全局加速器。用户明确要求的慢镜、氛围、舞蹈、产品观察或情绪停顿可用 `stylized_slow` 或省略 `pacing`。实际节奏仍需在生成结果中按节拍抽查；不能仅凭 Prompt 宣称达标。

当实时剧情明确不能接受长时间站立、摆姿或重复一个动作时，可为本镜增加 `pacing.max_idle_seconds`。它是生成后的可测验收门槛，不是全局快放开关：每一段超过该上限的画面必须发生可见的状态变化，否则即使总时长、分辨率和首帧都正确，也要判为节奏失败。

实时节拍不等于剧情覆盖。对于连续剧、小说改编或分镜，制作方还需声明 `narrative.objective` 和少量 `narrative.required_events`，把本镜不可替代的事实变化写清，并映射到节拍和首帧。这样可以识别“节奏有动作但核心付款、相认、交接或决定根本没有发生”的失败，而不是把过场动作误判为剧情推进。

### 8. QA auditor

编译器只产生检查计划，不伪造生成结果。生成后按本次任务核对：实际时长、分辨率、音轨、参考图角色、主体数量、关键时间点服装/动作、发型、身体比例、背景、裁切和结尾姿态。

### 9. Reference URL transport

图像语义决策属于 Codex，上传传输属于可替换的公共 URL 传输层。当前固定脚本使用 Uguu 的 `files[]` multipart 接口，所有 HTTP 客户端使用 `trust_env=False`，并对返回 URL 做一次新的 HTTPS GET、MIME/大小/SHA-256 校验。失败时停止，不自动换图床或重复创建视频任务。该流程是 host 无关的；上传后得到的 URL 是否被网关接受，仍由 provider profile 的输入契约决定。

### 10. Provider contract evidence

每次实际提交前，将参考图角色映射为当前 provider 明确支持的输入模式。profile 需要把以下内容分开记录：`client_contract`（MCP 发给网关的 JSON/字段）、`gateway_transport`（网关是否转成 multipart、Data URL 或其他格式）和 `upstream_contract`（上游实际要求）。记录的最小证据是 `host`、`profile`、`model`、日期、视觉输入模式、请求字段名、时长/分辨率、响应状态、是否拿到 task ID 以及生成后画面验收结果。官方直连文档只能作为候选契约，不证明兼容网关会转发同一字段。

MCP 的职责是发送与当前 profile 匹配的客户端请求，并把 profile 的认证状态用于成本闸门；MCP 不应把某个网关的内部 multipart 修复硬编码成所有 host 的行为。网关修复属于网关项目，必须通过对应 profile 的证据重新认证后才可写入状态。

出现 `video_image_input_required`、不支持输入模式或字段校验错误时，表示任务尚未创建；停止提交，不以同一素材轮换字段重试。必须先确认当前网关协议或显式取得用户同意进行一次受限认证。若只是视频内容与 Prompt 不符，而任务已经拿到 request ID，则不得把内容问题误判成接口问题，也不得自动重复付费。

## 安全与成本边界

- 编译器不访问网络、不上传参考图、不调用视频 API。
- 只有用户明确要求生成视频时才调用 `aiself-video`。
- 高风险报告不自动重试付费任务。
- 任务创建成功后，使用同一 profile 和 request ID 轮询/下载。

## 版本路线

### v1

JSON SceneSpec、Grok 风险规则、短 Prompt、测试和人工 QA 清单。

### v1.1

加入参考图预检和固定公网 URL 传输：尺寸、MIME、哈希、透明风险提示和 Uguu 上传验证；图像是否压平仍由 Codex 决策。

### v2

加入生成后媒体检查器：视频元数据、关键帧抽取、音轨存在性和简单人物/背景漂移标注。

### v3

支持分段生成计划和后期合成 manifest，而不是强迫单个 Grok 任务完成复杂时间轴。
