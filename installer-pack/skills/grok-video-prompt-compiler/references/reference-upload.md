# I2V 参考图 URL 固定流程

## 适用范围

当视频 MCP 需要 `reference_image_url`，而输入图片只在本地时使用。这个流程解决两个不同问题：

1. **图像语义问题**：拼贴、贴纸、透明层或非最终场景是否会污染 Grok 输入。这由 Codex 根据图像和风险审计决定。
2. **传输问题**：如何得到可访问、可验证的公网 HTTPS 图片 URL。当前 bundled implementation 使用 Uguu；这是公共 URL 传输层的默认实现，不是某个视频 host 的能力证明。

不要把两者混为一谈。上传工具默认上传原文件，不负责擅自去背、压平或删除贴纸。

## 关键接口语义

`reference_image_url` 的语义取决于本次视频接口的参数和调用方式。某些调用链会把它作为 I2V 首帧或强视觉锚点，某些调用链可能提供独立身份参考或关键帧角色；不能跨任务假定其中一种语义。当前调用前必须确认：图片角色、是否作为第 0 帧、是否有关键帧时间参数，以及接口是否支持角色分离。

## 决策规则

- 图片明确是本次任务的最终首帧：直接上传原图，前提是它的画面比例和构图符合目标。
- 图片明确只作身份参考：若接口支持独立身份角色，按该角色上传；若不支持，则只用于分析，并另准备任务所需的首帧或关键帧。
- 是透明 PNG 且透明区域可能保留旧拼贴/旧背景：先由 Codex 生成不透明处理副本，再上传副本。
- 是中央人物加四周人物/贴纸的拼贴：先确认拼贴是否就是本次目标画面；若不是，再准备符合本次主体数量、场景和机位的目标画面输入。单纯压平透明层不能删除可见贴纸。
- 参考图发型与本次画面要求冲突：按参考图角色准备对应输入；只有该图是首帧或关键帧时，才需要在该帧中呈现目标发型。
- 源图参与视频画面输入且比例与目标视频不一致：按目标比例重新构图，等比裁切或补背景，禁止拉伸；只有本次镜头要求全身时，才需要全身构图。
- 不确定图像在本次任务中是身份图、首帧还是关键帧：先停在预检阶段，报告角色和构图风险，不要靠重复上传解决语义问题。

## 当前默认传输方法

运行：

```powershell
python scripts/upload_reference.py --input C:\path\to\reference.jpg --output reference-url.json
```

当前脚本执行以下顺序：

1. 读取本地文件，限制为 JPEG、PNG、WebP 或 GIF，大小不超过 8 MiB。
2. 使用文件签名识别 MIME，不信任单独的扩展名。
3. 计算本地 SHA-256。
4. 使用随包 Python 运行时锁定的 `requests`，显式设 `Session.trust_env = False`、启用重定向并设置普通 User-Agent，向 `https://uguu.se/upload.php` 发送 multipart field `files[]`。`requests` 已包含在 `runtime/bundled/python-requirements.lock` 和离线 wheelhouse 中，无需用户单独安装依赖。
5. 解析 Uguu JSON，提取唯一返回 URL；HTTP 非 2xx、JSON 无 URL 或返回多个文件均视为失败。
6. 对返回 URL 发起一次新的 HTTPS GET，验证状态为 2xx、MIME 仍为允许的图片类型、大小不超过 8 MiB，并核对远端 SHA-256 与本地一致。
7. 只有全部验证通过才输出 `reference_image_url`。任何失败都停止，不自动换图床、不盲目重复上传。若未来某个环境不能使用 Uguu，应替换公共 URL 传输实现并保留同样的签名、大小、MIME、HTTPS 和远端哈希校验，不要把上传失败误判成模型不支持视觉输入。

## 网络与隐私

Uguu 返回的是公开 URL，且文件有服务端保留期限。只有用户明确要求生成视频并接受把图片上传到公开图床时才执行；不要把私人、敏感或不应公开的图片上传到此服务。普通环境代理会导致 TLS/连接错误，因此该工具固定使用 `trust_env=False`。

## 输出

输出 JSON 包含：`reference_image_url`、本地路径、MIME、字节数、本地 SHA-256、远端 MIME、远端字节数、远端 SHA-256 和 `verified=true`。视频 MCP 只使用验证后的 `reference_image_url`。
