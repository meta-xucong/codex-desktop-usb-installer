## 已验证失败模式

- 将直连模型的公开参数名直接套到兼容网关，或将历史成功当作当前网关的能力保证，可能导致图像字段被丢弃并返回 `video_image_input_required`。这种响应没有创建视频任务，不能通过切换猜测字段自动重试。
- 2026-08-14 的初始保护版本会以 422 在任何 R2V 图片下载或任务创建前停止，以避免把多图错误降级为 I2V。经 Wokey 文档和 Studio 证实后，部署的适配器改为显式 `multimodal_reference`：多图只会走有序 multipart 上传，`image` 与 `reference_images` 混用或显式 `image_to_video` 模式会在任务创建前报 4xx；不得回退为 I2V/T2V。
- 同一网关的 T2V 成功不证明 I2V 或独立身份参考可用。降级后的 T2V 必须明确标注为“未提交视觉参考、仅使用文字描述”，不得把提示词中的人物外观称为模型身份锁定。
- 拼贴被当成真实场景，四周人物持续存在。
- 透明 PNG 的底层 RGB 仍可能携带旧拼贴；是否压平由 Codex 根据输入语义决定，上传工具不默认改图。压平只解决透明底层像素风险，不能移除可见拼贴人物。
- 当本次目标帧要求高马尾而输入帧披发时，发型会漂移；该目标帧应直接包含目标发型。
- 当本次任务要求固定全身时，模型仍可能裁切或转近景；对应画面输入需要完整留边。
- `reference_image_url` 传入身份肖像时，原图可能直接成为第一帧；Prompt 中说“仅作参考”不足以改变这个输入语义。
- 1:1 近景图强行适配 9:16 时，若客户端或中间流程非等比缩放，人物会明显变长；即使不拉伸，模型从半身补全全身也会造成比例漂移。
- 将多个叙事动作、对白、店员和主观心理压入单个 15 秒任务时，Grok 会优先保留少数视觉动作，导致原文信息大量省略。
- 精确节点常出现约数百毫秒的偏差。

## 选择建议

Grok 更适合“视觉目标明确、镜头变量可控的短片”。多人物漫剧情节、复杂动作、贴纸交互和多次换装并非一律禁止；应根据主体数量、互动、镜头和时间轴要求逐项审计，必要时再采用分镜拆段、后期合成或更适合严格控制的模型。

接口适配必须先于 Prompt 优化：先确认当前 `host + profile + model` 是否把图片识别为首帧、独立参考还是根本不支持该模式；确认后才选择上传、构图重建和生成策略。

## 认证规则

- `certified` 只表示该 profile 的指定模型、输入语义、字段和限制在明确日期有成功证据。
- `uncertified` 表示有配置但还没有足够实测；`unknown` 表示没有可靠配置；`unsupported` 表示当前 profile 明确没有该能力。
- T2V 成功不能认证 I2V；I2V 成功不能认证独立身份参考或时间关键帧。
- 网关字段能被接受不等于上游使用了图片。至少结合 task ID、响应、开头关键帧和本次输入语义做验收。
- 非 Aiself host 只能复用协议族的实现，不应自动复用 Aiself 的限制或能力状态；应在该 profile 写入自己的证据。
- 上游返回明确 Prompt 字节上限时，将它记录为对应 `host + profile + model + mode` 的 `max_prompt_bytes`，并在本地预检/创建前检查；没有这类证据时，`4096` 之类的本地质量预算只能告警，不得充当硬拒绝。
