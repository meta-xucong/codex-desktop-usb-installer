# 用户研究

系统化用户洞察框架，从数据中挖掘真实需求与行为模式。

## 研究维度

### 1. 用户画像构建

**基础属性**：
- 人口统计（年龄、性别、地域、收入、教育）
- 职业特征（行业、职位、工作年限）
- 技术素养（数字产品使用熟练度）

**行为特征**：
- 使用场景（时间、地点、设备）
- 使用频率与时长
- 决策路径与触点

**心理动机**：
- 核心诉求（功能需求/情感需求/社会需求）
- 痛点与焦虑
- 期望与愿景

**画像模板**：
```
用户画像：[名称，如"效率追求者小李"
- 基本信息：28岁，互联网产品经理，一线城市
- 典型场景：通勤时间用手机处理工作
- 核心痛点：工具分散，信息同步麻烦
- 关键诉求：一站式解决方案，节省时间
- 决策因素：口碑推荐 > 功能完备 > 价格
```

### 2. 痛点挖掘

**痛点分类**：
- 功能性痛点（功能缺失、体验差）
- 情感性痛点（焦虑、挫败感）
- 经济性痛点（成本高、性价比低）
- 社会性痛点（身份认同、社交压力）

**挖掘方法**：
- 用户评论情感分析
- 社群讨论热点追踪
- 客服反馈整理
- 竞品差评分析

**痛点优先级评估**：
- 样本内观察到的发生频率（高/中/低；说明样本和分母，不外推为总体发生率）
- 痛苦程度（严重/一般/轻微）
- 解决意愿（强烈/一般/无感）

### 3. 需求验证

**需求真伪判断**：
- 是"需要"还是"想要"
- 是否愿意付费
- 是否有现有替代方案
- 解决后是否愿意推荐

**验证方法**：
- 问卷调研（定量）
- 深度访谈（定性）
- MVP测试
- 预售验证

### 4. 用户旅程分析

**旅程阶段**：
1. 认知（如何知道产品）
2. 考虑（对比评估过程）
3. 决策（购买/注册转化）
4. 使用（核心功能体验）
5. 留存（持续使用动力）
6. 推荐（口碑传播行为）

**分析要点**：
- 每个阶段的触点与情绪
- 流失节点与原因
- 关键时刻（Moments of Truth）

## 数据来源

优先使用当前 Codex 会话提供的网页搜索/浏览能力，并区分公开观察、用户原话和研究者推断。
如果网页能力不可用，只使用用户提供的访谈、数据、链接和文件，并明确样本与实时性限制。

- 用户访谈与问卷
- 产品数据分析
- 社交媒体与公开社群讨论
- 客服与反馈系统
- 应用商店评论
- 行业研究报告

## 推断边界与数据保护

- 区分用户原话、观察到的行为、研究者解释和待验证假设；引用结论时记录对应证据。
- 结论只适用于实际接触到的样本和研究场景。访谈、便利抽样、社群评论或自愿问卷不能单独支持总体占比、市场规模或人群普遍性结论。
- 报告样本数量、招募渠道、纳入条件、时间范围、分母和未答情况。定性研究以主题和反例呈现；若提供样本内计数，写明 `n/N`，不得改写成目标人群占比。
- 只有设计能支持总体推断时，才估计总体比例。通常需要明确目标总体与覆盖充分的抽样框、按已知/可估纳入概率进行的概率抽样、足够的有效样本，以及可说明的加权和方差/区间估计方法；不能通过事后加权把便利样本变成概率样本。若采用其他抽样设计，须说明其推断依据和限制。定性目的抽样、便利/自愿样本、社群评论通常只支持样本内主题或计数，不支持总体比例。报告加权方法、非应答/覆盖偏差和不确定性区间。条件不满足时明确写“本样本观察，不能据此估计总体比例”。
- “已验证需求”必须注明验证方法、样本/数据范围、实际观察到的证据和限制。自述的意愿不能写成已观察的购买或使用行为。
- 数据收集遵循目的限定和最少必要原则；尽量去标识化，避免不必要地收集或输出敏感个人信息。公开可访问不代表可以不受限制地复用；遵守来源条款、适用隐私要求和研究参与者的合理预期。
- 区分用户说的和实际做的；注意幸存者偏差，覆盖流失用户及不同用户类型，并以合适的方法交叉验证。
