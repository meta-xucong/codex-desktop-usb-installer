# 用户研究

系统化用户洞察框架，从数据中挖掘真实需求与行为模式。

## 研究维度

### 1. 用户画像构建

**基础属性**：
- 人口统计（年龄、性别、地域、收入、教育）
- 职业特征（行业、职位、工作年限）
- 技术素养（数字产品使用熟练度）

**行为特征**：
- 使用场景（时间、地点、设备）
- 使用频率与时长
- 决策路径与触点

**心理动机**：
- 核心诉求（功能需求/情感需求/社会需求）
- 痛点与焦虑
- 期望与愿景

**画像模板**：
```
用户画像：[名称，如"效率追求者小李"
- 基本信息：28岁，互联网产品经理，一线城市
- 典型场景：通勤时间用手机处理工作
- 核心痛点：工具分散，信息同步麻烦
- 关键诉求：一站式解决方案，节省时间
- 决策因素：口碑推荐 > 功能完备 > 价格
```

### 2. 痛点挖掘

**痛点分类**：
- 功能性痛点（功能缺失、体验差）
- 情感性痛点（焦虑、挫败感）
- 经济性痛点（成本高、性价比低）
- 社会性痛点（身份认同、社交压力）

**挖掘方法**：
- 用户评论情感分析
- 社群讨论热点追踪
- 客服反馈整理
- 竞品差评分析

**痛点优先级评估**：
- 发生频率（高/中/低）
- 痛苦程度（严重/一般/轻微）
- 解决意愿（强烈/一般/无感）

### 3. 需求验证

**需求真伪判断**：
- 是"需要"还是"想要"
- 是否愿意付费
- 是否有现有替代方案
- 解决后是否愿意推荐

**验证方法**：
- 问卷调研（定量）
- 深度访谈（定性）
- MVP测试
- 预售验证

### 4. 用户旅程分析

**旅程阶段**：
1. 认知（如何知道产品）
2. 考虑（对比评估过程）
3. 决策（购买/注册转化）
4. 使用（核心功能体验）
5. 留存（持续使用动力）
6. 推荐（口碑传播行为）

**分析要点**：
- 每个阶段的触点与情绪
- 流失节点与原因
- 关键时刻（Moments of Truth）

## 数据来源

优先使用当前 Codex 会话提供的网页搜索/浏览能力，并区分公开观察、用户原话和研究者推断。
如果网页能力不可用，只使用用户提供的访谈、数据、链接和文件，并明确样本与实时性限制。

- 用户访谈与问卷
- 产品数据分析
- 社交媒体与公开社群讨论
- 客服与反馈系统
- 应用商店评论
- 行业研究报告

## 注意事项

- 区分用户说的和实际做的
- 避免幸存者偏差（关注流失用户）
- 样本要覆盖不同用户类型
- 定性定量结合，交叉验证
