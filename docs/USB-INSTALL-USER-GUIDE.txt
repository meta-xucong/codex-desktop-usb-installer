Codex U 盘版 v0.5.24 — 使用说明
================================

一、该运行哪个文件
------------------

请双击 U 盘根目录的：CodexDesktopSetup.exe

看到 Windows 用户账户控制（UAC）时点击“是”。
不要直接运行 CodexAppManager.exe，也不要直接打开 apps\Codex 里的 Codex.exe；
这些入口可能绕过正常的一键流程或 U 盘授权检查。


二、这一版把什么放在哪里
------------------------

U 盘：

  apps\Codex                 Codex 程序本体（安装后生成）
  content\skills             兼容性目录；完整内容随 codex-starter-kit 提供
  content\mcp                兼容性目录；MCP 资源由能力包安装到本机
  content\codex-starter-kit  完整 Skills、Agents、运行时和 MCP 离线能力包
  ccswitch                   Codex Switch 程序
  payload                    经校验的离线 MSIX 原始载荷

本机用户目录（通常在 C 盘）：

  %USERPROFILE%\.codex       Codex 配置、账号/会话及 CLI 共用状态
  %APPDATA%\Codex            桌面端漫游数据
  %LOCALAPPDATA%\Codex       桌面端本地缓存和日志

本版不会在 U 盘创建 WindowsApps、WpSystem，也不会把 Codex 用户数据通过
Junction 链接到 U 盘。若本机账户主动把用户配置目录重定向到了这只 U 盘，安装器
会停止并提示，避免误报为“数据在本机”。


三、第一次安装
--------------

1. 将完整发行文件夹复制到 U 盘；不要只复制 EXE。
2. 双击 CodexDesktopSetup.exe。
3. 在 UAC 窗口点击“是”。
4. 等待载荷校验和安装完成。大 MSIX 的签名校验可能需要数分钟，请勿拔盘。
5. 管理器会自动打开 CCSwitch，并从已签名 U 盘授权中自动加载该 U 盘唯一的用户 API Key。
6. 不需要在 CCSwitch 中手工填写、保存或启用 API Key；首次启动即会自动创建/更新
   `404TOKEN（unified-api-internal）` 供应商并切换启用。该 Key 对应统一 API 分组可用的
   模型集合，不按模型拆分。
7. 返回管理器启动 Codex。

如果 U 盘尚未完成“注册账号并签名”，管理器不会猜测或生成 Key；请回到受信任的签名
工具重新处理一份干净发行包。签名工具目录不属于运行期 U 盘包，不能把管理员 Key
或签名工具一起交给终端用户。

管理器会自动为 Codex Switch 使用软件渲染、恢复并前置真正的主窗口。启动 Codex 时
也会先尝试软件渲染；若目标电脑的 Chromium 沙箱与显卡驱动冲突，会自动清理失败
进程并完成一次兼容重试，不需要用户手工添加启动参数。

安装器会自动检测 WebView2 和 VC++ x64 运行库。缺失时只使用 U 盘中已固定哈希、
微软签名的完整离线安装包补齐；不会下载 DLL，也不会关闭杀毒软件。

Codex 安装验证通过后，管理器还会自动导入 U 盘内的完整能力包：包括全部随包
Skills、Agents、离线 Python/Node 运行时以及本地 MCP 资源。这个步骤失败不会回滚
已经验证成功的 Codex，安装完成页仍会保留重试入口。


四、日常使用
------------

每次都从 U 盘根目录的 CodexDesktopSetup.exe 进入。

使用过程中保持 U 盘连接。拔掉 U 盘后有约 5 秒宽限，管理器会结束本产品启动的
Codex 和 Codex Switch。重新插回同一只授权 U 盘后可以再次打开；历史配置和数据仍
从本机用户目录读取。

不要移动或改名以下内容：

  CodexDesktopSetup.exe
  CodexAppManager.exe
  manifest.json
  usb-manifest.json
  SHA256SUMS.txt
  payload、apps、content、ccswitch、resources 文件夹

不要手工修改 WindowsApps、WpSystem、PackageRepository 或相关 ACL。v0.5.20+ 新装
路线不使用它们；若旧版本留下 AppX 状态，应由管理器的兼容清理流程处理。


五、Skill、Agent 和 MCP
----------------------

一键安装成功后，管理器会自动执行 `content\codex-starter-kit\install-all.ps1`，
把随包的 Skills、Agents、运行时和 MCP 支持文件安装到当前 Windows 用户目录。
运行时和安装清单会写入 `%USERPROFILE%\.codex\codex-agent-kit`；用户配置仍由
Codex 使用本机目录，U 盘不保存密钥。

如果自动步骤失败，或以后需要修复/补装，可在安装完成页底部不显眼的“组件修复”入口
单独重跑能力包安装。入口里每个外部连接默认关闭；不勾选或不填写就跳过，不会发起
外部 API 请求。可选项包含飞书 MCP、DashScope 搜索、Image-2 和 Seedance 的
API/路由配置，密钥只通过当前用户环境变量传给本次安装，不写入 U 盘或日志。

同一入口还提供 CCSwitch 单独重试按钮，适合 Codex 已安装但 CCSwitch 因运行库、
WebView2 或窗口启动问题没有自动打开的情况。

如果 CCSwitch 显示 `localhost` 连接被拒绝，先关闭任务栏/任务管理器中残留的旧版
CCSwitch，再点击管理器中的 CCSwitch 重试；CCSwitch 采用单实例端口，旧版本占用时
新版本不能接管。若卸载页面显示“卸载未完成”，先退出 Codex、CCSwitch 及其残留窗口，
展开详情确认失败步骤后再重试；管理器不会把未确认删除的文件误报为已清理。

不要把 API Key、OAuth token 或登录凭证放入 `content\skills`、`content\mcp` 或
能力包目录。


六、卸载
--------

在管理器中选择“卸载 Codex + Codex Switch”。

普通卸载会删除本产品受管组件，但默认不触碰 U 盘发行目录，也保留本机 Codex 数据。
这是为了避免删除官方 Codex 或 Codex CLI 也在使用的配置和登录信息。

如果明确选择“清除 Codex 个人数据”，界面会列出本机路径（包括能力包安装的
%USERPROFILE%\.agents\skills）并要求再次确认。该操作不可恢复，也可能影响同一
Windows 账户下的官方 Codex/CLI；能力包登记的当前用户环境变量也会一并清理，
但不会扫描或清空其他环境变量；U 盘中的能力包不在本机数据清理范围内。

当前 USB 版默认不创建可绕过 U 盘授权的开始菜单入口。卸载流程仍会清理本产品旧版
曾创建的、且能证明目标指向本产品便携目录的 Codex/ChatGPT/CCSwitch 快捷方式，
覆盖当前用户、公共开始菜单和桌面；无法证明归属的同名快捷方式会保留。新的卸载报告
统一写入本机 %LOCALAPPDATA%/CodexAppManager/logs（不可写时回退到 %TEMP%），
不会继续散落到桌面。管理器启动时还会自动清理已证明归属且目标已不存在的死链，
有效快捷方式和无法核验归属的同名链接不会被碰。

如果同时选择“删除 U 盘安装介质”，管理器会先卸载 apps\Codex，再严格复核发行包
哈希。存在未知文件、用户自行加入的 Skill/MCP 或文件被修改时，会保留介质并报告，
不会静默删除用户内容。

usb-license.json 是管理器为当前物理 U 盘生成的可变身份文件，不属于不可变发行哈希
清单。卸载器会在看门狗停止前取得当前租约指纹，二阶段再复核卷身份、发行清单、
许可证及其原子备份均未变化，最后才直接删除许可证和卸载入口；不依赖 U 盘回收站。
名称相同但内容、产品、指纹或签名不匹配的文件不会被删除。若存在其他未知项目，
卸载报告会逐项列出并保留介质，便于用户先自行移走文件后重试。


七、常见提示
------------

“权限不足”
  请确认启动的是 CodexDesktopSetup.exe，并在 UAC 中点“是”。标准用户需要输入
  管理员凭据。企业 WDAC/AppLocker/组策略阻止时，产品不能绕过，需要管理员处理。

“载荷校验超时或失败”
  不要拔盘。换到健康的 USB 端口重试；若哈希失败，请重新完整复制发行目录。

“用户数据目录指向 U 盘”
  本机 USERPROFILE、APPDATA 或 LOCALAPPDATA 被重定向到产品 U 盘。请恢复正常的
  Windows 用户目录后再装；安装器不会在这种状态下继续。

“安装成功但找不到开始菜单 Codex”
  这是当前设计。直接 Codex 快捷方式会绕过 U 盘授权，请从
  CodexDesktopSetup.exe 启动。

“点启动后短暂等待”
  管理器正在确认 Codex 是否出现稳定、可操作的窗口；只有进程但没有窗口不会被误报
  为成功。首次在不兼容显卡环境上可能自动进行第二次兼容启动，后续同一 Codex 版本
  会复用已验证的模式。

“CCSwitch 打不开 / localhost 已拒绝连接”
  先关闭所有旧版 CCSwitch 进程，再从 U 盘根目录重新打开管理器或点击 CCSwitch
  重试。不要同时运行安装目录中的旧版 `CodexSwitch.exe`；单实例冲突会导致新窗口
  无法监听本机端口。确认 U 盘仍连接且 `ccswitch\CodexSwitch.exe` 未被杀毒软件隔离。

“卸载未完成”
  关闭 Codex、CCSwitch 和相关编辑器后再次执行卸载，并展开详情查看具体路径/进程。
  只有管理器确认所有受管文件已退出并完成删除后才显示完成；未知文件、被占用文件
  或权限策略会被保留并明确列出，不应直接强删整个 U 盘目录。

“U 盘根出现 WindowsApps 或 WpSystem”
  它们不是 v0.5.20+ 新装路线应产生的内容，通常是旧版残留。先保存日志，通过管理器
  的卸载/兼容清理处理，不要手工夺权或强删。


八、反馈安装失败时请保留
------------------------

  %LOCALAPPDATA%\io.github.wangnov.codexappmanager\logs\codex-app-manager.log
  %LOCALAPPDATA%\CodexUsbGuard\status.json
  界面“展开详情”里的完整文字
  U 盘根目录的 manifest.json、usb-manifest.json（不要发送 API Key）

请同时说明 Windows 版本、U 盘盘符、是否点击了 UAC“是”、安装前是否运行过旧版。
