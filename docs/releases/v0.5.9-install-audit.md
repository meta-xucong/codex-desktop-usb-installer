## 诊断结论与修改方向

1. 不再沿用“缺管理员权限”的旧结论：附件本轮的 token 检查和前置条件已成功。策略值 1 读回成功不代表所有 Windows SKU 都实际执行，也不代表程序或数据已经落在正确卷。
2. `AllowDeploymentInExternalVolumes` 未找到微软策略或本机 ADMX 依据，不新增该值，不自动开启开发者模式。真正的 `RestrictAppToSystemVolume`：未配置/0 不禁止其他卷，1 禁止，类型/数值异常与读取失败单独报告。`RestrictAppDataToSystemVolume` 是不同的数据策略。[微软策略定义](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-applicationmanagement#restrictapptosystemvolume)
3. 实际 MSIX 清单为 `OpenAI.Codex 26.825.5331.0 x64`，最低系统 `10.0.19041.0`；目标机 19045 满足。清单未发现强制系统盘声明。不能据此保证每台机器都能部署到 USB，也不能反过来把家庭版直接判为不支持。
4. 系统卷上曾留下每机共享/staged payload，是“指定 D: 却注册到 C:”的一项有依据的候选；尚无目标机安装前 AllUsers/provisioned 状态，不能锁死根因。增加精确身份的只读机器级快照和共享冲突保护，不自动删除其他用户或预配包。[微软维护者关于 staging/register 的说明](https://github.com/microsoft/winget-cli/discussions/1983)
5. 本轮新增且身份相符的错盘注册，先尝试一次受限 `Move-AppxPackage`，复查最终位置；迁移失败再做安全回滚。这不是主动向 C: 安装的 bootstrap。[Move-AppxPackage](https://learn.microsoft.com/en-us/powershell/module/appx/move-appxpackage?view=windowsserver2025-ps)
6. 原生补救的四参数 `AddPackageAsync` 不支持 `ForceUpdateFromAnyVersion`，原来把枚举成员加入该重载存在 `E_INVALIDARG` 风险；改为仅使用该重载支持的参数，不静默改变降级语义。[微软接口契约](https://learn.microsoft.com/en-us/uwp/api/windows.management.deployment.packagemanager.addpackageasync?view=winrt-19041)
7. AC 回滚阻断已与源码对应，但附件未提供 reparse tag/target。本机只读检查到的 AC 是普通目录，不能替代目标结构。改为允许严格验证的同包根内目录链接，复制并哈希核验实际数据；外部/未知/循环链接仍保护并输出具体诊断。不按 `AC` 名称、报告“0 MB”或“安装前目录不存在”免备份。后者在安装期间存在用户启动程序写入数据的窗口，已由独立审查指出并撤回。

8. 独立审查 IR-04 在第一次冻结版本 `AE79B293…` 找到数据位置 gate 只看目标盘符的漏洞：卷 GUID 或多跳重定向会被记录为未知却仍成功。审查者用纯模拟复现，已退回修复，首次构建不用于交付。已有数据必须能确认位于本机系统卷；无法解析则保持 USB 包并明确未完成，避免假成功。若尚未创建数据，允许安装准备完成但明确 `not-created` / 首次运行后待验收，不主动启动 AppX 或制造数据目录来假装取得证据。

## 尚待现场证据与使用边界

- 目标 AC 的 `Attributes / LinkType / Target` 及 reparse tag 未提供。不能把其实际结构认定成已覆盖的同包内部链接；未知/外部数据仍会保留。新日志会直接给出链接及数据位置诊断。
- “指定 USB 但注册到 C:”的真实触发因素仍需本次新增的 AllUsers/预配快照印证；共享 staging 是候选，不是已证实根因。遇到共享冲突不能以自动删除他人注册解决。
- 首次 AppX 数据尚未创建时，准备完成不代表数据位置已经被实际验证。Home 系统是否实施数据策略也不能只用注册表读回值证明。
- 真机仍需完成：已有自有 C 包的保留数据迁移、首次安装、普通卸载后重装、明确选择清数据的卸载；实际 `InstallLocation` 必须为该 U 盘，数据位置必须可确认在本机。
- 若新版说明“程序已在 U 盘，但数据位置未确认”，保持现状并提供新日志；不要靠反复卸载/清数据尝试。无必要不接管 WindowsApps/WpSystem 权限。

本轮完成的是证据支持的代码缺陷修复、安全边界及发布验证；不把安全拒绝、模拟通过或包的 `ready` 值等同于用户目标已经完整达成。
