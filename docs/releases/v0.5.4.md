# Codex App Manager v0.5.4

## USB AppXVolume 错盘安装回归修复

本版针对 v0.5.3 在部分 Windows 版本上出现的“日志显示 sideload completed，
但 `Get-AppxPackage` 实际位于 C:\Program Files\WindowsApps”问题发布。

- USB AppX 部署脚本在 `Add-AppxPackage`、WinRT `PackageManager` 和系统卷
  bootstrap/`Move-AppxPackage` 全部路径完成后，强制复核当前用户的
  `InstallLocation` 驱动器根必须等于本次 U 盘根目录。
- 如果本次安装原先没有 Codex 注册，却意外在系统卷创建了注册，脚本会在报错前
  用 `Remove-AppxPackage -PreserveApplicationData`（目标系统支持时）清理该新注册，
  并等待当前用户注册消失；已有外部注册不会被这条安全清理删除。
- 错盘结果现在明确返回 `expectedPackageVolume`、`actualPackageVolume`、
  `actualInstallLocation` 和清理结果，不再把 C 盘注册当作 USB 安装成功。
- Rust 层对“成功但没有目标卷证据”的旧版脚本结果也会触发一次针对当前 U 盘的
  卷注册/重试，最终仍无法落到目标卷时停止，不回退到 C 盘便携版。
- USB 安装提交边界再次确认管理器本身为高完整性令牌；未取得管理员令牌时在关闭
  Codex 或调用 AppX 之前停止，避免由中完整性进程替代安装账户或产生半成功状态。
- 所有需要管理员令牌的 PowerShell 子操作会先用 `whoami /groups` 验证高完整性 SID。
  UAC/企业策略未真正提升时，错误会明确指出“管理员子进程未获得高完整性令牌”，
  而不是只显示模糊的 HKLM `Access is denied`。
- 较长的 AppX PowerShell 脚本改用带 UTF-8 BOM 的临时 `.ps1` 文件传输，避免超过
  Windows CreateProcess 命令行长度后出现 `os error 206`；短探测仍保持内联执行。

## 验证边界

本版已完成 Windows 主机上的 Rust 单元测试、PowerShell 生成脚本解析测试、错盘静默
成功模拟测试，以及 USB 包静态清单/哈希验证。真实 `Add-AppxPackage`、UAC、企业策略和
可移动 NTFS AppXVolume 的最终验收仍需在目标 Windows 10/11 机器上进行。

如果目标机仍失败，请把错误详情中的以下字段一并提供：

```text
operation=
targetVolume=
expectedPackageVolume=
actualPackageVolume=
actualInstallLocation=
wrongVolumeCleanupError=
```

这些字段可以区分“管理员令牌没有真正取得”“卷注册失败”“AppX 忽略了 `-Volume`”和
“错盘注册清理失败”四类问题。
