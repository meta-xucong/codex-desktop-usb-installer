# v0.5.16 — 孤儿 AppX 机器状态修复与发行审计

日期：2026-09-06。范围：目标机 v0.5.15 在 USB AppX 卷、载荷签名和依赖均通过后，因 `Get-AppxPackage -AllUsers` 返回精确 Codex FullName、但 `InstallLocation` 为空而被共享包门禁阻止。旧 v0.5.15 发布目录保持原样。

## 根因与处理边界

目标机的对象不是普通“已安装 Codex”，也不能仅凭一条 `PackageRepository` 注册表路径就直接删除。v0.5.15 把所有“当前用户查不到、机器查询却存在”的对象统一当作共享／暂存／预配包，未区分下列状态：

- 其他用户已安装或系统预配：必须保留并停止；
- 精确包已健康暂存在绑定 USB：可继续 Register，不应删除；
- 只有一个与已验证载荷 FullName 完全一致、没有已安装用户和预配记录、位置为空／悬空／已不存在的对象：属于可受控修复的精确孤儿机器状态。

v0.5.16 新增完整分类器。只有第三类才能进入自动修复；不同版本、多个机器对象、未知发布者、任一 `Installed`／未知用户状态、任一预配记录、路径读取失败或非目标普通路径仍然 fail-closed。`Staged` 仅表示机器暂存，不等同于某用户已注册；其他用户真正的 `Installed` 状态不会被移除。

## 已实现的修复

1. **所有权快照**：同一次预检读取当前用户、`-AllUsers` 和 provisioned 状态，输出 `classification/reason/fullName/locationState/ownerStates`。查询错误不是“没有包”。
2. **路径证据**：复用 v0.5.15 的 AppX 路径解析，只把空路径、已确认不存在的路径或悬空精确系统 Junction 视为孤儿候选；未知／拒绝访问不授权清理。
3. **先保数据再清状态**：在任何移除调用前，对当前用户精确包数据做无重分析点逃逸的备份、清单及 SHA-256 复核，并写入绑定 SID、载荷哈希、USB／系统物理卷的 `recovery.json`。数据不存在也要在调用前后复核，防止竞态创建。
4. **两条 Windows 正式接口**：先调用 `Remove-AppxPackage -Package <exact FullName> -AllUsers`，重新查询；若记录仍是同一个精确孤儿，再复核数据和所有权，调用 WinRT `PackageManager.RemovePackageAsync(fullName, RemovalOptions.RemoveForAllUsers)`。只有重新查询证明机器对象消失才继续 Stage。
5. **中断可恢复**：日志记录 `machineRepair=pending/running/completed`。若正式接口已经提交而程序在结果复核前中断，下一次从原日志恢复，先查询确认对象已消失，不会重复移除，再继续 Stage/Register 和原数据恢复。
6. **失败保留现场**：两条接口都失败、返回后对象仍在或所有权发生变化时，不部署、不改用户数据、不把失败报成已清理；错误中保留两条接口结果、最终分类、恢复阶段和日志路径。
7. **禁止私库手术**：生产脚本不包含 `AppModel\PackageRepository` 路径，不使用 `Remove-ItemProperty`，不夺取 TrustedInstaller/SYSTEM 所有权。协议扩展及数据库一致性交给 AppX 部署服务处理。
8. **受限语言兼容**：新增运行脚本只使用普通哈希表，不依赖受限语言会拒绝的 `[pscustomobject]` 转换。既有企业策略门禁仍然生效，不能也不会绕过 WDAC/AppLocker/UAC。

## 故障模拟矩阵

所有 AppX 包、卷、用户、进程与部署接口均为临时目录／PowerShell 夹具；开发机没有执行真实 `Add/Move/Remove-AppxPackage`、没有写 HKLM，也没有修改 `WindowsApps`。

| 场景 | 期望与结果 |
| --- | --- |
| 精确 FullName、无用户、无预配、空 `InstallLocation` | 备份 → 日志 → `Remove-AppxPackage -AllUsers` → 证明消失 → Stage/Register → 原数据恢复；通过 |
| PowerShell 移除失败、WinRT 移除成功 | 二次数据／所有权复核后走 `RemovePackageAsync(RemoveForAllUsers)`；通过 |
| 两条正式接口都失败 | 机器对象与用户数据保留，Stage/Register 均为 0，日志停在 `machineRepair=running`；通过 |
| 移除已提交、复核前进程中断 | 第二次运行识别对象已消失，不重复 Remove，继续安装并恢复数据；通过 |
| 精确包已在绑定 USB 健康暂存 | 不当作孤儿、不删除，继续受控注册；通过 |
| 其他用户 `Installed`、预配包、不同版本、多对象或查询失败 | 任何 Remove/Stage/Move/Register 均为 0；通过 |
| 受限语言模式 | 无自定义对象转换回归；通过 |

## 目标机验收

复制整个 `usb-oneclick-v0.5.16` 目录到 U 盘，双击根目录 `CodexDesktopSetup.exe`，在标准 UAC 中点“是”。不要单独复制 EXE，也不要混用 v0.5.15 文件。

本次 v0.5.15 失败现场的预期日志顺序为：`classification=orphan-exact` → 数据备份／`machineRepair=running` → 某一正式移除 API → `classification=none` → USB Stage/Register → 程序卷与本机数据卷后置核验。若仍失败，请保留完整管理器日志和 `CodexAppxDataBackups\...\recovery.json`；不要手动删除恢复日志、`WindowsApps` 或 `PackageRepository`。
