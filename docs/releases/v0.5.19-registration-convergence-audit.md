# v0.5.19 注册收敛与安装误报修复审计

日期：2026-09-06

## 结论

现场报告的两个结论需要分开看：

- v0.5.17 遇到的“无安装用户、无预配记录、包文件已丢失”的 staged 孤儿确实存在。该问题已在 v0.5.18 通过“已验签 MSIX 精确重水合 + Windows 公开 AppX API 清理/迁移”处理，安装和联合卸载共用该链路。
- 补记 G5 属于新的真实缺陷：Windows 事件日志和 `Get-AppxPackage` 已证明 PackageUser 注册成功，但 `DeploymentResult.IsRegistered=false` 仍被当作失败，导致管理器显示“安装未完成”。

报告中的 StateRepository 手工删表只能说明现场状态可被强制修复，不能作为产品实现。v0.5.19 仍禁止直接编辑 StateRepository/PackageRepository、夺取 WindowsApps 所有权或修改其 ACL。

## 根因

Windows 10 的 AppX 部署异步对象完成，与当前用户包投影可见，并非同一个同步时刻。`RegisterPackagesByFullNameAsync` 可以已经成功提交 PackageUser，事件 400 也已经记录成功，但返回对象中的 `IsRegistered` 仍为 `false` 或查询投影稍晚才出现。

旧逻辑把 `IsRegistered` 当成最终事实，因此会出现：

1. U 盘 Stage 已成功；
2. 当前用户注册已由 Windows 提交；
3. 管理器却抛出 `Recovery registration did not complete`；
4. 恢复日志停在 registering，用户误以为安装失败并再次卸载/重装。

## 修复

### 1. `IsRegistered` 降级为诊断提示

恢复注册和外层 WinRT 兼容安装都只记录 `isRegisteredHint`、ActivityId 和原生错误。非零 `ExtendedErrorCode` 仍立即失败；单独的 `IsRegistered=false` 不再决定成败。

### 2. 独立后置条件

原生 Register 返回后，最多等待 60 秒，以只读方式重复验证：

- 当前 Windows 用户只能看到一个精确 `PackageFullName`；
- 包身份为 `OpenAI.Codex_2p2nqsd0c76g0`；
- `Status` 存在时必须为 `Ok`；
- `IsPartiallyStaged` 存在时必须为 `false`；
- `InstallLocation` 解析后必须是绑定 U 盘 `WindowsApps\<FullName>`；
- 所有权回调确认无其他用户或预配冲突；
- USB 卷、系统卷和当前用户 SID 在等待期间没有变化。

查询异常只会被记录并继续有限重试，绝不会被当作“未安装”或“成功”。出现其他版本会立即停止，不用等待掩盖冲突。

### 3. 恢复日志区分两个阶段

`lastDeployment.state=completed` 只表示原生调用完成；`postconditionState` 单独记录 `pending-current-user-query`、`observed-current-user-package` 或 `timed-out`。成功观察还会保存 `registrationPostcondition`。这些字段在续接前校验身份、次数和类型，防止被损坏的日志授权恢复。

如果原生调用已完成但观察超时，下次重试先查询已提交注册；已经收敛时不会重复 Stage 或 Register。

### 4. 覆盖外层兼容路径

不仅受控数据恢复脚本，旧的 `Add-AppxPackage` / WinRT URI 兼容重试路径也已删除 `IsRegistered` 成功门禁，统一使用当前用户精确包的健康投影，再执行 USB 位置核验。非零 WinRT ExtendedError 不再被返回值掩盖。

### 5. 孤儿卸载边界保持不变

v0.5.18 的精确孤儿重水合继续用于安装前修复和联合卸载：仅当 FullName、签名、SHA-256、无用户、无预配记录、记录卷唯一且路径状态可证明时，才恢复缺失包字节并调用公开的移除/迁移接口。歧义状态继续停止并留证。
