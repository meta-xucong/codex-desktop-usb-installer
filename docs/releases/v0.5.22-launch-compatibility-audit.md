# v0.5.22 启动兼容与可操作窗口审计

## 结论

v0.5.21 的便携安装事务已经成功，目标机失败发生在安装后的“可用性交付”阶段：
Codex 的 Chromium GPU 进程在 Windows 10 19045 + Intel 核显环境退出，CCSwitch
虽然产生进程和主窗口，但窗口没有可靠前置。旧实现把“成功创建进程”当成“用户可用”，
因此会出现界面宣称完成、用户却看不到程序的假成功。

v0.5.22 将验收条件改为真实 GUI 后置条件，不改动 v0.5.20 起已经验证的程序/数据
分离结构，也不恢复 AppXVolume 路线。

## 现场证据如何转化为实现

### Codex

- USB 便携启动先传入 `--disable-gpu`，规避目标机的 GPU 进程致命退出。
- 最多等待 20 秒寻找执行文件位于精确 `apps\Codex` 根目录内的进程窗口。
- 只有宽度至少 320、高度至少 200 的顶层窗口才是候选；Chromium/Tao 的 14×14
  内部 bookkeeping HWND 不是产品窗口。
- 窗口必须在三秒后仍然存在，避免 Electron 出现瞬时 HWND 后因
  `GPU process isn't usable` 退出却被误报成功。
- 如果仅软件渲染失败，先按精确程序根关闭本次残留进程，再自动用现场已验证的
  `--disable-gpu --no-sandbox` 重试一次。
- 只有兼容重试真正显示稳定窗口后，才把该选择按 Codex 版本写入本机；版本变化后
  重新从较安全的 sandbox 模式探测。
- USB 子进程强制关闭自更新，避免便携目录原地更新和无包身份 updater 错误；设置不
  污染用户的官方 Codex 或系统环境。

`--no-sandbox` 是兼容性末级回退，会降低 Chromium 子进程隔离，不作为默认参数，
不写入全局环境，也不作用于别的软件。

### CCSwitch

- 通过子进程环境变量 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--disable-gpu` 使用
  软件渲染，保留用户已有的其他 WebView2 参数并保证幂等。
- 校验执行文件后从 U 盘原目录启动，配置仍由 CCSwitch 写入本机用户目录。
- 必须检测到尺寸正常的顶层窗口，才返回 `launched=true`；20 秒内只有后台进程或
  微型内部窗口时，关闭本次精确根目录内的进程并报告明确错误，避免单实例锁污染重试。
- 恢复最小化/隐藏窗口，将其位置钳制到最近显示器工作区并提升到普通 Z 序顶部；随后
  最小化管理器并再次请求前景激活，让 API Key 配置入口确实可见。

现场报告把 14×14 HWND 判断为“安装向导”。复核 CCSwitch v3.14.1 源码后，正常主窗
口配置是 1000×650、最小 900×600 且启动时先隐藏再显示；因此 14×14 更符合
Tao/WebView2 内部窗口。v0.5.22 不盲目放大它，而是忽略它并呈现真正的主窗口。

## 旧看门狗升级缺陷

此前 `%LOCALAPPDATA%\CodexUsbGuard\CodexUsbGuard.exe` 只在文件不存在时复制。用户
更换新版 U 盘目录后，本机仍可能长期运行旧 helper，继续写出旧的路径文本或租约行为。

新流程比较当前管理器与本机 helper 的长度和 SHA-256。不同则先删除旧租约、等待旧
helper 在五秒内退出、回收陈旧 PID 锁，再复制到唯一临时文件、校验哈希、原子改名，
最后才签发新租约和启动 helper。失败时拒绝静默继续使用旧二进制。

## 不变量与剩余边界

- 程序仍位于 U 盘 `apps\Codex`，用户数据仍位于 Windows 正常用户目录。
- 进程发现、窗口操作和失败清理都以规范化后的精确程序根 + PID 为边界，不按全局
  `Codex.exe` / `CodexSwitch.exe` 名称粗暴结束其他安装。
- 不修改显卡驱动、Defender、UAC、系统 WebView2 全局参数或 Chromium 全局沙箱策略。
- 自动测试可以验证参数选择、窗口过滤、版本记忆、旧 helper 内容比较、编译和发布
  完整性；目标机 GPU/窗口前景限制仍需最终物理机验收。

## 验收标准

1. 安装完成后自动出现可操作的 CCSwitch 主窗口，而不是只存在后台进程。
2. 用户保存并启用 404TOKEN API Key 后，从管理器启动 Codex；不兼容机器无需手工
   VBS 或参数即可看到稳定窗口。
3. 首次兼容回退成功后，同一 Codex 版本下次直接使用已验证模式；更新版本后重新探测。
4. 拔盘五秒只结束当前租约登记且执行文件位于本产品根目录的进程。
5. 从 v0.5.21 或更早版本升级时，本机看门狗二进制自动变成当前管理器的同哈希版本。
