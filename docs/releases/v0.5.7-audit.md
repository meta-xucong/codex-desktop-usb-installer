# v0.5.7 WorkBuddy 变更复审与安装/卸载加固

日期：2026-09-04。此文及 USB-INSTALL-USER-GUIDE.txt 是当前基线；旧文档中系统卷 bootstrap、策略失败后继续安装、保留数据无保障重试等描述废止。

## 结论

WorkBuddy 的“由 manager 原生写注册表”可以减少 PowerShell Provider 的中间步骤，予以保留。但其根因论断和验证强度不成立：

- `CreateProcess` 正常使用调用进程的安全上下文；不能从 HKLM 拒绝访问反推“已提权进程一定丢失了令牌”。ACL、具体请求的访问权、既有键与父键权限、注册表视图都需要证据。[Microsoft CreateProcessW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw)
- TrustedInstaller 是所有者不等于 Administrators 的允许权限失效；不应靠改所有权、扩大 ACL 来修复。
- 导入表含 RegSetValueExW、编译通过、窗口存活 5 秒，都不能证明 HKLM 写成功，更不能证明 USB 部署成功。
- `PreserveApplicationData` 仅适用于开发中的 loose-file 注册；不是“凡 AppX 部署都支持”。`0x80073CFA` 是通用卸载失败，不能单凭它进行会丢数据的重试。[Microsoft Remove-AppxPackage](https://learn.microsoft.com/en-us/powershell/module/appx/remove-appxpackage?view=windowsserver2025-ps)

## 已确认的代码问题与改造

| 问题 | 改造原则 |
| --- | --- |
| 现有键仍申请建子键等多余权限；读取失败当作不存在 | 原生、最小权限、统一视图、区分不存在/拒绝/类型错误，读回核验 |
| 策略写入后才记 journal；恢复前不看是否被别人改动 | 写前留恢复证据，恢复比较当前值，核验后才清 journal |
| token 数据缓冲和组标志判断不严；whoami 文本依赖语言 | 有边界和对齐的原生令牌检查，明确拒绝 deny-only；子进程非文本判断 |
| 已有 WindowsApps 重复强制创建 | 优先使用现有在线注册，仅缺失时创建/注册 |
| 辅助进程输出管道可能堵塞、运行库安装无等待上限 | 有界等待和输出处理，保留实际错误；不强杀共享组件 servicing |
| USB 失败路径仍先向 C 盘 Add 再 Move | 删除全部系统卷 bootstrap，只允许显式 USB 目标；错误放盘不能报成功 |
| USB 部署复用会暂停 Windows Update/DO 的历史恢复流程 | USB 模式不再暂停机器级更新服务或清更新缓存；并发部署冲突直接报错 |
| Move 失败会删除已有包再重装 | 失败停止并保留原包；只允许清理本次新增的错误注册 |
| no-preserve 重试可能删除用户选择保留的数据 | 限定兼容错误；普通包无保留参数卸载前做可核验备份，备份失败停止 |
| Get-AppxPackage 查询异常被吞成不存在 | 用严格 Result 验证安装/卸载终态，错误不能显示已卸净 |
| 空白机直接运行 Tauri EXE 无 WebView2 | 增加界面前检测、原生错误弹窗、完整离线运行库及哈希/签名门禁 |
| 按压缩大小/固定值检查 U 盘空间 | 按 MSIX ZIP 目录展开总量、文件分配开销和工作余量预检 |
| 正式 usb-oneclick 目录不存在，旧包与新 manager 易混用 | 重建完整 v0.5.7 目录，校验两个 EXE 清单及全包哈希 |
| 多次点击入口会重复启动界面前运行库检查 | USB 管理员会话专用单实例锁；不把激活转发给低权限旧管理器；原有跨进程操作锁继续保留 |
| 预检失败一律提示载荷丢失，失败页不方便清理 | 改为真实预检错误提示；失败页提供卸载入口；安装终态验证通过后才删暂存证据 |

## 部署约束

安装器在修改 AppX 前必须确认 `RestrictAppDataToSystemVolume=1` 可读回及目标卷已在线；不再把策略失败降级为“继续安装”。`RestrictAppToSystemVolume=1` 是明确禁止 USB 的系统策略，只诊断、不篡改。微软说明该数据策略是设备级，影响所有用户，并列出 Pro/Enterprise/Education 等支持版本；不能保证 Home/精简系统行为。[Microsoft ApplicationManagement](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-applicationmanagement#restrictappdatatosystemvolume)

这里保证的是失败不假装成功、不主动落到 C 盘、不静默删已有程序。注册表拒绝、企业策略、AppX 服务故障、坏盘、系统更新待重启等外部条件仍可能使安装失败，不能承诺任何电脑都成功。

当前仍以登录用户自身为管理员的 UAC 同意流程为使用基线。标准账户输入另一管理员的凭据会改变进程身份，不能承诺应用会注册给原标准账户。

策略恢复记录目前属于当前用户，而策略本身是机器级。不能宣称多 Windows 账户同时安装/卸载时有全局引用计数；本版以单一使用账户为验收范围。备份是保留副本，不自动恢复进新安装。

WebView2 x64 完整离线包来源为微软 `https://go.microsoft.com/fwlink/p/?LinkId=2124701`，本次固定文件 258,510,544 字节，SHA-256 `1f4638309f3d82c31a3028c3cf7d75998f58e4d1407380f5cb8a8e9172caf17d`。组件在构建时核验微软数字签名，运行时匹配内置哈希，不为绕过信任检查而关闭签名校验。完整包随 USB 产物交付，因超过 GitHub 普通文件限制不纳入源码 Git blob。

## 验证方法

当前 MSIX 含 5,962 项，展开总量 1,961,182,190 字节；新 USB 空间预检要求复制安装包后仍有至少 2,522,473,454 字节空闲（约 2.35 GiB）。这纠正了旧说明“1 GB 空闲即可”的不足；Windows 自身的临时空间、更新和备份还可能需要额外余量。

运行 Rust 单元测试、执行 mock PowerShell 安装/卸载分支、HKCU 临时注册表测试、前端测试及发布校验。Mock 需覆盖错误放盘、已有包迁移失败、访问拒绝、参数不支持、备份失败、查询失败等，而不是只有字符串断言。

本机不执行真实 Codex 安装/卸载，不改变现用 HKLM 策略、不关闭用户正在使用的 Codex。最终日志中的真实 Windows AppX 行为，仍需目标电脑验收。具体本轮命令、数量、发布哈希另列于 v0.5.7-validation.md。

## 真机验收

1. 全新 Windows、NTFS U 盘，确认 UAC → 缺运行库自动补齐 → 安装 → USB InstallLocation → Key 配置。
2. 先卸载保留数据，再安装；检查备份路径与新应用数据路径；不要用“不见文件夹”代替注册状态验证。
3. 已有 C 盘 Codex：迁移成功才更新；模拟迁移失败应保留原包。
4. UAC 取消、策略禁止 USB、磁盘满/只读、断盘：明确失败，不新增 C 盘注册，不伪报成功。
5. 反复打开及卸载，AppX 注册查询失败要显示未知/失败；共享 VC++/WebView2 不随产品卸载。
