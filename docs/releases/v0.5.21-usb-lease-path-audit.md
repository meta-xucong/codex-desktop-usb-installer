# v0.5.21 USB 租约路径修复与审计

## 结论

v0.5.20 的安装失败不是 MSIX、UAC、许可证或 U 盘指纹失效，而是同一套件路径的两种
Windows 文本表示被当成了不同授权对象。v0.5.21 删除了安装入口对 `status.json` 完整
路径的裸字符串授权，改为在写入前重新观察当前可执行文件所在套件，并用当前进程拥有的
租约指纹三元组核验。

目录改名、复制到其他 U 盘、锚点内容变化和租约 PID 不一致仍会失败；本修复不会削弱
原有 U 盘绑定。

## 现场证据

目标机报告的同一会话中：

- `status.json.bundlePath` 的实际值包含两个连续分隔符：
  `D:\\usb-oneclick-v0.5.20-final`；
- `lease.json.bundlePath` 为 `D:\usb-oneclick-v0.5.20-final`；
- `volumeSerial`、`anchorSha256`、`bundleRelativePath` 三项一致；
- 看门狗状态为 `authorized/running`，载荷签名和哈希通过；
- 点击安装立即报“当前安装器目录与已授权 U 盘租约不一致”，且 `apps\Codex` 尚未创建。

代码复核确认 `scan_removable_for` 将已经以 `\` 结尾的 `D:\` 与另一个以 `\` 开头的
相对后缀直接拼接；`authorized_usb_codex_root` 随后又将状态快照中的完整路径与
`current_exe` 父目录进行原始文本比较。这两处组合后可以确定性复现报告。

## 修复

### 1. 统一路径生产

- 扫盘候选路径由盘符根和经过验证的相对组件构造，不再手工增加第二个根分隔符；
- 观察已存在套件时先调用 `fs::canonicalize`，解析 8.3 路径和目录重分析点；
- 再去除 `\\?\` / `\\.\` DOS 命名空间、合并重复分隔符、移除 `.`；
- 拒绝 UNC、盘符相对路径、`..`、冒号注入和 NUL。

规范化路径只用于状态展示、日志和安全落点构造，不充当授权身份。

### 2. 授权改用稳定身份

安装动作入口现在执行：

1. 要求状态为 `authorized/running`；
2. 从当前运行管理器重新定位并观察真实套件目录；
3. 读取本机租约并验证 schema、product、当前 manager PID；
4. 比较 `(volumeSerial, anchorSha256, bundleRelativePath)`；
5. 从观察到的真实套件路径重新读取 `usb-license.json`，复核许可证/签名及其与租约一致性；
6. 仅将观察到的规范化真实目录下精确的 `apps\Codex` 交给安装事务。

`status.json.bundlePath` 和 `lease.json.bundlePath` 不再参与等值授权。若指纹真的不同，错误
详情会同时给出当前/租约路径、卷序列号、相对目录和锚点摘要，便于现场定位。

### 3. 保持产品约束

- 同一实体的重复分隔符、verbatim 前缀、大小写和 8.3 表示不会误拒绝；
- 改名会改变 `bundleRelativePath`，继续拒绝；
- 复制到另一 U 盘会改变卷序列号，继续拒绝；
- 修改 manifest/usb-manifest 会改变锚点哈希，继续拒绝；
- 其他进程或陈旧租约 PID 不能授权安装；
- `apps` 或 `apps\Codex` 为 Junction/符号链接时继续拒绝。

## 回归覆盖

- 等价路径规范化：普通 DOS、重复分隔符、`\\?\`、`\\.\`、`.`；
- 拒绝 UNC、`D:relative`、`..`；
- 扫盘路径根分隔符恰好一个；
- 完整路径文本不同但指纹一致时授权通过；
- bundle 相对路径或 owner PID 不一致时授权失败且包含诊断值；
- 原有五秒拔盘、许可证签名和进程范围测试继续通过。
