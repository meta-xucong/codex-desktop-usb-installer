# Codex App Manager v0.5.6

## 安装/卸载兼容性修复

v0.5.6 针对目标机日志中出现的“提权成功但 HKLM 仍拒绝”和“安装错盘后卸载失败”两条链路做了收口：

- USB 管理器的提权判定不再只看完整性级别。现在同时要求 `TokenElevation`、非
  `TokenElevationTypeLimited`，并通过有效的内置 Administrators SID 成员校验；PowerShell
  子进程启动后还会用 `whoami /groups` 拒绝 `deny only` 过滤令牌。取消 UAC、标准用户无凭据或
  企业策略阻止提权都会在真正修改 AppX 之前失败并给出诊断。
- AppX 卷注册仍使用 Windows 标准 `requireAdministrator`/`runas` 同意，不修改执行策略、不关闭
  Defender，也不绕过 WDAC/AppLocker 或企业注册表 ACL。策略键写入被企业策略锁定时，策略会作为
  明确警告；目标卷注册本身失败则停止安装。
- 安装脚本的错盘清理、数据卷冲突清理和显式卸载共用同一窄分类：只有 Windows 返回
  `0x80073CFA`/“PreserveApplicationData 仅适用于 deployment mode”，或当前 AppX 模块
  明确没有该可选参数时，才对同一个当前用户包改用不带标记的普通卸载。普通 Access denied、
  锁定、身份或策略错误不会被掩盖；无标记路径会明确提示包内数据不保证保留。
- USB 安装继续执行目标卷后置校验。`Add-AppxPackage` 即使返回成功但实际落在 `C:`，也会先清理
  本次新建的错误注册，再尝试一次原生 WinRT `PackageManager` 目标卷部署；无法证明落到 USB 时
  fail-closed，不创建 portable/C: 副本。
- 卸载在每个包和每次重试后轮询当前用户 `Get-AppxPackage`，只在注册真正消失后报告主卸载成功。
  若兼容性重试去掉 Preserve，结果会明确提示包内数据不保证保留；“保留我的数据”关闭时仍由
  上层显式清理已知 Codex 用户目录。

## 验证

本版本包含 Windows PowerShell 模拟回归：

- 模拟 `Add-AppxPackage` 静默落到 `C:`、`Remove-AppxPackage -PreserveApplicationData` 返回
  `0x80073CFA`，确认安装报告失败时不会留下错误注册；
- 模拟显式卸载同一错误，以及模块缺少 Preserve 参数，确认卸载成功并产生数据保留警告；
- 模拟普通 Access denied，确认不会触发破坏性降级重试。

真实 Windows 10/11 + NTFS 可移动卷仍需在目标机点击 UAC 后验收。AppX 服务不可用、企业策略、磁盘
只读/损坏、UAC 被用户取消或安全软件隔离等外部条件不能由安装器合法绕过。
