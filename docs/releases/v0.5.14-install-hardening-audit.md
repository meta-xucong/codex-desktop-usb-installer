# v0.5.14 安装链路复审与补强

## 范围和基线

用户要求再次整体检查安装失败的潜在漏洞并直接修复。基线是 v0.5.13；本轮原样基线文件保存在 `D:\AI\AGENT_U盘\.codex-audit\v0.5.14-baseline`。工作区既有修改保留，没有重新拉取依赖、提交推送或改动旧发行目录。审计由主控直接完成，没有声称独立 Agent 审查。

复核覆盖入口提权、静态 CRT、离线 WebView2/VC++、USB 身份、清单与载荷验证、本地暂存、依赖预检、卷注册和策略事务、按卷 Stage、精确 Register、恢复记录、版本/位置/健康复核、CCSwitch 衔接及联合卸载兼容。本轮不在开发机运行真实 AppX 安装/卸载、注册表策略修改或用户数据清理。

## 新发现与修复

1. **重复安装会先删除暂存包。** v0.5.13 无论内容是否正确都先要求额外 1.5 倍包大小的空闲空间，再删除同名暂存文件。Windows 部署仍持有该文件、文件继承源的只读属性，或缓存已经占用剩余空间时，重试可能反复失败。v0.5.14 先校验缓存大小与 SHA256，正确即原位复用，然后照常重验 Authenticode；不需要额外复制空间。不正确、不可读或非普通文件的旧尝试保留，改用同一产品暂存根下的 SHA256 缓存槽，后续重试可再次复用；该槽也损坏时才进入 UUID 隔离目录。新文件以 `create_new` 写入，不继承源文件的只读属性，不覆盖并发创建的文件。完整写入和哈希仍须通过。
2. **固定 USB MSIX 模式漏掉已确认的依赖缺失。** 旧代码只在允许便携回退时利用预检结果；固定模式发现必要框架缺失后仍会进入部署。新增门禁在修改策略、关闭 Codex 和调用部署前明确报告缺少的名称／版本／架构。未知探测结果保持未知，不误当缺失；本版载荷清单未声明额外 PackageDependency，因此不随意新增下载和系统组件。
3. **包已注册不等于恢复完成。** 原有托管记录、同版本和 USB 落点即可让界面显示“此版本已经安装”，忽略仍有效的 recovery.json。新增 `recoveryPending`，同时识别主记录与 `.bak`，读取错误或异常对象也不当完成；已归档的 completed 记录不阻塞。界面显示“继续完成安装”，安装结束后还会复查，未完成则保留暂存证据并停止自动启动 CCSwitch。USB 安装器的 Codex 启动入口也检查该状态，避免在待恢复期间写入应用数据。该标记只判断是否需要收尾，不代替引擎对 SID、载荷、物理卷及记录内容的严格校验。
4. **损坏的残留 ASAR 可使状态探测异常分配。** MSIX 流式读取已有 1 MiB package.json 限制，已安装树的可 seek 读取却没有。破损头中的超大 size 可能在安装器读取旧版本时引起分配失败／进程终止。现在两个读取分支均拒绝超限声明；新增完全内存内的恶意长度夹具，无需分配大内存或接触真实应用数据。
5. **恢复重试重复要求整份 USB 空间。** 包已 Stage 到 U 盘时，管理器旧门禁仍要求再腾出完整展开包空间，导致本可完成的 Register／数据恢复被阻断。首次安装保留原前置检查；有待恢复记录时，将空间决策交给完成记录、卷身份、SID、载荷校验的恢复引擎。引擎只有查到精确、健康的已暂存 USB 包才跳过新的 Stage 预算；找不到则检查“展开大小 + 文件分配余量 + 512 MiB”后才 Stage。repair 需要移除现有包时，在 Remove 前也检查完整预算。有记录不等于有包，错误／篡改记录不授权跳过部署和数据安全检查。

## 保留并复核的约束

- 入口和 USB Manager 均使用 `requireAdministrator`；管理员确认仍由 Windows 完成，启动标志本身不代表实际提权。
- Authenticode 仍在本地副本校验，5 分钟有界；USB 部署预算 10 分钟。没有移除签名或哈希校验。
- USB 包按绑定的 PackageVolume 和精确 FullName 查询，禁止 C 盘 bootstrap 回退。原生 Stage 完成后仍核对实际路径；Register 显式指定系统数据卷。
- 失败恢复保留写前记录和备份；没有通过删除 recovery.json、跳过 AC/junction 校验、接管 WindowsApps ACL 或删除共享包来“让安装继续”。
- v0.5.13 的精确 staged-only 包清理、恢复证据延迟删除、TEMP 独立清理及终态报告规则保持有效。

微软文档交叉核验：`RegisterPackagesByFullNameAsync` 面向当前用户，最低 Windows 10 2004 / 19041，符合当前载荷最低版本；按卷查询的单字符串重载参数是 packageFamilyName。[注册 API](https://learn.microsoft.com/en-us/uwp/api/windows.management.deployment.packagemanager.registerpackagesbyfullnameasync?view=winrt-26100)、[按卷查询 API](https://learn.microsoft.com/en-us/uwp/api/windows.management.deployment.packagevolume.findpackages?view=winrt-26100)。继续使用程序卷／数据卷两项已文档化策略的区分，没有新增未经证实的开关。[ApplicationManagement 策略](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-applicationmanagement#restrictapptosystemvolume)。

## 尚需真实机验证的边界

本轮修复的是可确认的软件缺陷，不证明所有 Windows 镜像均可安装。组织策略禁止部署、AppX 服务损坏、介质 I/O 错误、空间确实不足、缺少管理员凭据或安全软件阻止仍可能失败，并须依据真实 HRESULT/ActivityId 处理。待恢复记录与原 USB／用户／载荷不匹配时会停止保护数据；不能随意换一只 U 盘接管旧恢复记录。

Windows 10 19045 目标机上真实 Stage/Register、应用首次运行和卸载终态仍需现场验收；隔离测试不会被写成实机成功。
