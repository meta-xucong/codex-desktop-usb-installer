# v0.5.8 卸载残留清理：范围、实现与验收

日期：2026-09-04。依据用户提供的 `codex-uninstaller-cleanup-spec(1).md` 对照当前源码，不把报告中的推测当作事实。本版替代 v0.5.7 关于“安装器缓存不清理、备份不随数据清除、安装载荷始终保留”的卸载说明。

## 一、纠正诊断

- `operation.lock` 是使用 fs4/Windows 文件锁的载体；文件存在本身不是“正在安装”的证据。进程结束后 Windows 释放其文件锁。不能在仍有句柄时盲删锁文件，否则可能出现两个不同文件对应两个锁的并发风险。[Microsoft LockFile](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-lockfile)
- 数据策略此前已有 journal 和恢复实现；用户报告末尾的实测也写明策略已回滚。新增的是更完整的终态检查与卷所有权记录，不是删除整个系统策略键。
- `AllowDeploymentInExternalVolumes`、`AllowDevelopmentWithoutDevLicense` 不是当前安装代码的写入项；`AllowAllTrustedApps` 只读探测。没有原值快照不能默认设为 0 或删除。
- `Remove-AppxVolume` 要求卷内没有任何用户的暂存应用。卸载本用户 Codex 不等于整个卷可删除；USB 拔出也不等于 Windows 已注销卷。[Microsoft Remove-AppxVolume](https://learn.microsoft.com/en-us/powershell/module/appx/remove-appxvolume?view=windowsserver2025-ps)

## 二、用户可选择的范围

默认卸载程序、运行状态、缓存及安装暂存，保留个人数据和源安装包。关闭“保留我的数据”后进入永久数据清除的第二次确认。另有独立的“同时删除当前 U 盘安装包”开关；即使保留个人数据，擦除安装包仍需二次确认。

| --- | --- | --- | --- |
| 当前用户 OpenAI.Codex AppX 注册、托管便携程序 | 卸载 | 相同 | 不删除其他用户注册；注册查询失败不当作已卸载 |

## 三、两阶段实现

1. 前端显示范围及不可恢复数据警告，后端依然要求一次性卸载令牌和显式确认。源安装包擦除不接收任意前端路径，只从当前进程映像定位。
2. 第一阶段继续执行严格 AppX/CCSwitch 卸载，恢复 journal 中记录的环境变量与系统策略、处理终态事务，注销可证明由本产品新建且真正空的 USB AppX 卷。未完成的恢复证据不删除。
3. 把同一个静态 CRT 管理器复制为唯一批次的原生清理组件，使用特殊入口在 Tauri、日志、运行库、守护初始化之前分流。校验原/副本哈希、原管理器 PID+创建时间+映像、已知用户目录。
4. 清理组件保留现有管理员会话单实例对象，再发送就绪握手；管理器只在就绪后退出。清理组件等待原进程句柄结束，不按名称杀同机程序。此时前端是“待最终清理”，不是“所有痕迹已清空”。
5. 集中目录清单驱动本地清理，有界重试、路径越界/重解析检查和删除后复核。Codex 与 CCSwitch 的清数据选项独立传递，退出后再次清理和复核其已确认目录，防止退出前重建数据。数据清理失败时保留源安装包供排错；有意保留的配置、共享状态在报告中声明。
6. 可选源包擦除另外验证介质身份和确认时的元数据，不把盘符相同当作同一 U 盘；清理时固定目录/文件句柄、校验并删除同一文件对象，不递归删除源目录，未知文件/被改文件不强删。管理器与入口最后删除；末尾失败尽力恢复入口与身份清单，已删除的大载荷不会自动恢复。清理组件/收尾进程使用各自安全工作目录，避免自己占用待删目录。
7. 最终报告按项写入结果；短生命周期系统组件只清理这一批次的自身文件，不注册服务、计划任务或开机删除项。只有本地目标、所选介质清理及组件自清理均核验完成，才算所选范围完成。

## 四、不能承诺的“零痕迹”

这是产品卸载，不是安全取证擦除。不会删除 Windows 事件日志、Prefetch、系统安装历史、还原点、共享运行库，也不会擦除他人文件或用改权限/关闭安全软件的方式强制删除。用户可能主动复制过安装器到其他目录；没有归属记录的副本不能全盘搜索后自动删除。

旧版没有记录的系统卷归属和注册表原值不可追溯重建；本版对未来新写入记录精确快照，对历史未知情况保留并报告。占用文件、坏盘、企业策略、断盘、未知恢复事务可以使卸载部分失败；失败不能显示“彻底完成”。

## 五、验证要求

自动测试必须覆盖：双确认范围、退出前 pending 而非成功、空目录/不存在的幂等性、嵌套文件与无关文件隔离、只读文件、占用句柄、链接/盘符替换拒绝、保留数据与清除备份分支、未恢复 journal 阻止数据删除、系统/共享/暂存卷拒绝注销、空 USB 卷删除后复核。

真实验收仍须目标电脑执行：安装→普通卸载→再次安装→彻底清除→可选删除安装包；确认最终报告各项及 helperFinalization 状态。开发机测试未实际卸载现用 Codex、未修改 HKLM、未清理本机真实用户数据目录。最终测试数量与发布哈希另见版本验证记录。

## 六、测试隔离问题与实际影响

本轮发现旧版 portable 单元测试没有隔离 Windows 元数据函数，会向开发机当前用户的真实 HKCU 卸载项和开始菜单写入合成测试条目。现已把这四个写入/删除函数排除在测试编译之外，后续回归不再操作真实快捷方式或卸载登记；生产实现仍使用归属校验。

修复前测试留下两个已核实的测试条目：

- `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\Codex`，指向不存在的 `%TEMP%\codex-portable-observer-64728\Codex`。
- `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Codex.lnk`，指向不存在的 `%TEMP%\codex-portable-replace-test-66312\Codex\Codex.exe`。

对这两个精确合成条目的清理尝试被工具安全策略在执行前拒绝，未绕过重试，因此仍保留。旧测试没有记录写入前的原值，不能宣称恢复了未知的原始快捷方式/登记状态。另一个早期失败的清理测试保留了 `%TEMP%\codex-media-cleanup-中文 空格 ' 测试-86b28a7a-e931-4807-80d8-391fd1f50f3b` 中 5 个微小模拟文件；对该精确夹的清理也被策略在执行前拒绝，未绕过。该情况不涉及真实 AppX 卸载或 HKLM 变更，但属于本轮测试的实际副作用，应明确披露。

此次格式化工具还整理了 engine 的若干相邻模块格式；因工作区原有未提交修改，未以覆盖文件的方式回退它们，以免丢失原有工作。语义改动、构建与验证以当前工作区和版本验证记录为准。
