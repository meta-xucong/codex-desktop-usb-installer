# v0.5.24 U 盘许可证与卸载二阶段审计

日期：2026-09-06。输入现场为 Windows 10 19045 上 v0.5.21 的完整卸载报告：
主卸载已经删除 `apps\Codex`，但“删除 U 盘安装介质”的二阶段把管理器启动时自动
生成的 `usb-license.json` 判为 `SHA256SUMS.txt` 清单外未知文件，因此保留整套介质。
现场 28 个不可变发行文件全部哈希一致，唯一额外文件就是该许可证。

## 结论

报告对 v0.5.21 的根因判断成立。这不是 U 盘损坏，也不是回收站故障，而是两种文件
模型冲突：不可变发行清单只描述出厂文件；`usb-license.json` 却是管理器拥有、运行时
生成且必须随物理 U 盘携带的可变身份元数据。把它当普通“未知文件”会形成自锁。

许可证仍保存在 U 盘，而不迁到本机。它绑定卷序列号、发行锚点和 bundle 相对路径，
是跨电脑识别同一物理介质的组成部分；迁到 `%LOCALAPPDATA%` 会把设备身份错误地变成
单机状态。正确修复是显式建模并验证它，而不是把所有同名文件加入无条件删除白名单。

## 实现

1. 卸载入口在停止看门狗以前重新观察当前 bundle，并用当前 manager 进程持有的租约、
   实际可移动卷、完整许可证和发行锚点获得 `UsbFingerprint`。路径文本和盘符不作为
   授权凭据。
2. 介质预检仍固定目录/文件对象并校验 `SHA256SUMS.txt`；`usb-license.json` 及原子
   `.bak` 作为有类型的可变元数据处理。它们必须是普通文件、大小受限、JSON 可解析，
   `schemaVersion`、`product`、UUID、时间戳、三元指纹及配置的 Ed25519 签名均通过。
3. 二阶段计划升级到 schema 3，保存卸载前取得的完整指纹；介质快照同时保存不可变
   清单、USB manifest、主许可证和备份的 SHA-256。父进程退出后，helper 会重新核对
   卷身份与全部快照，防止交接窗口内被换盘或替换许可证。
4. 删除顺序保持事务边界：先清理已验证载荷和空目录，许可证、清单、manager、入口
   均作为重试身份保留到最终提交；末尾失败会尽力恢复这些小型重试文件，不会伪报
   “全部清理完成”。可移动盘直接使用固定句柄删除，不依赖回收站。
5. 未知文件/目录和重解析点仍 fail closed，但预检现在汇总并逐项列出所有阻断路径，
   不再只返回笼统的“二阶未完成”。伪造、损坏、错产品或错指纹许可证也只会保留，
   不会因为文件名相同而被删。
6. 旧 schema 1/2 helper 仍可被严格识别并清理；新 schema 3 残留也加入下一次启动的
   精确清理范围，避免升级后遗留 20 MB helper 目录。

## 安全与可用性边界

- “删除 U 盘安装介质”仍需要用户单独勾选并确认；普通卸载不会删发行包。
- 用户放入的 Skill、MCP 或其他未知内容不会被强制删除。产品不提供绕过这条保护的
  隐藏强删路径。
- 管理器与二阶段 helper 都继承标准 `requireAdministrator` UAC 令牌；管理器自己能
  创建许可证的正常 NTFS U 盘也应能由同一身份删除。被企业 ACL、WDAC/AppLocker、
  磁盘写保护、介质拔出或安全软件硬性阻止时只能准确报告，不能安全绕过。
- 自动测试只删除自己创建的临时夹具，不在开发机上执行真实 AppX/HKLM 修改，也不
  运行真实卸载。
