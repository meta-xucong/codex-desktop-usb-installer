# G18：离线启动可见性修复

## 结论

本次修复只处理“断网双击后长时间没有任何界面”的 P0 问题，暂不构建、暂不打包，等待能力包热更新器合并后统一发布。

报告中提到的 `update.404token.xyz` 和 `skins.agentsmirror.com` 在当前源码中是更新/皮肤功能的配置或用户操作入口，并不在 Windows 生产首屏调用链上。`OfflineHome` 首次加载只调用本地 Tauri IPC：离线载荷探测、本机 Codex 状态和 U 盘授权状态；更新检查和在线皮肤目录分别位于用户主动进入/点击的功能中。静态生产 CSP 也只允许本地应用源、IPC 和本地资源。因此，不能把二进制中出现 URL 字符串直接当成“启动期网络请求”的证据。

真正的启动脆弱点是：

1. Windows 发布版主窗口配置为 `visible=false`；
2. 窗口显示被拆成两个前置条件：WebView2 原生快捷键安全配置完成、前端发送 `frontend_ready`；
3. 前端 readiness 超时原来是 10 秒，而且仍会被 WebView2 显示门闩拦住；
4. 如果 WebView2 没有触发页面加载事件，原来的前端 fallback 也不会发生，用户只能看到“进程存在但没有窗口”。

## 已落地的修复

### 1. 原生安全回调完成后立即显示本地启动壳

`src-tauri/src/lib.rs` 中，WebView2 浏览器快捷键禁用成功后立即请求恢复主窗口，不再等待 React readiness。生产窗口展示仍然受安全回调保护，因此没有绕过 Ctrl+P/Ctrl+R/F5 的原生拦截策略。

### 2. HTML 首屏自带无依赖启动骨架

`index.html` 现在内嵌纯 HTML/CSS 启动提示：

- 不依赖 React、字体、远程资源或任何 IPC；
- WebView2 只要能呈现本地文档，用户就能看到“正在启动本地界面”；
- React 正常挂载时由 `bootstrap.tsx` 清理后替换，不会残留重复内容。

### 3. 前端 readiness 回退缩短到 3 秒

前端 readiness 仍用于 native shell 事件路由，但不再决定窗口是否可见。3 秒后进入 degraded 状态并尝试显示窗口；若 WebView2 安全门闩仍未完成，则转入原生提示路径。

### 4. 增加独立的 5 秒原生启动看门狗

看门狗从主窗口创建后立即启动，不依赖页面加载事件。5 秒内 WebView2 安全回调仍未完成时，使用 Windows 原生消息框提示：当前不需要联网、尚未执行安装/更新，并建议重启和检查本地 WebView2 运行库。前端 watchdog 与 WebView watchdog 共用一次性标志，避免重复弹框。

## 安全边界

- 没有把窗口显示提前到 WebView2 安全配置之前；
- 没有恢复任何启动期远程更新/皮肤请求；
- 没有改变 U 盘签名、Codex 安装、能力包安装或 CCSwitch 流程；
- 本轮没有生成安装器、U 盘布局或签名文件。

## 验收标准

| 场景 | 期望 |
|---|---|
| 正常联网启动 | WebView2 安全配置成功后立即出现本地启动壳，随后进入正常 UI |
| 完全断网启动 | 不等待远程站点；窗口仍出现，或最迟约 5 秒出现原生提示 |
| React/前端 chunk 异常 | 窗口可见，进入静态 crash fallback，而不是隐藏进程 |
| WebView2 安全回调延迟 | 不静默；原生 watchdog 提示一次 |
| 用户主动检查更新/在线皮肤 | 仍按原有网络功能执行，不影响首屏离线启动 |
