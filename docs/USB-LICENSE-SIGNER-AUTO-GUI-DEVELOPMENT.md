# U 盘签名器自动化 GUI 开发文档

状态：已实现；正式 Bundle 已支持 SignedRequired 公钥绑定。

目标：把签名器的用户流程收敛为“插入 U 盘 → 双击签名器 → 点击一次签名”。用户不选择密钥文件、不填写 KeyId、不选择候选目录；程序自动识别唯一的合格 U 盘 Bundle，并在条件不满足时停止。

## 1. 用户可见行为

- 只扫描可移动 NTFS 卷。
- 必须发现且只发现一个完整、干净的 Bundle。
- 空 U 盘、非 NTFS U 盘、多个候选、清单/哈希/载荷不完整、存在 `apps/Codex` 安装运行树，均直接报错并不写入 U 盘。
- GUI 自动发现签名机当前 Windows 用户可解密的 DPAPI 密钥；找不到时首次自动初始化一个本机用户绑定密钥。
- GUI 不显示 KeyId、DPAPI Blob 路径或文件选择器。密钥文件只保存在签名机本地 `%LOCALAPPDATA%\CodexUsbLicenseSigner\keys`，不会复制到 U 盘。
- 签名按钮只有在 Bundle 声明的签名策略、公钥指纹与本机密钥完全匹配时才可用。
- 签名成功后仍自动回读、验签和深度检查；结果未知时不提示成功，也不允许直接重复写入。

## 2. 不能省略的安全约束

管理器不是在运行时任意信任 U 盘中的公钥，而是使用构建时内置的 Ed25519 公钥和 KeyId。因而“自动生成密钥”只能表示：首次在签名机本地自动创建并用 Windows DPAPI（当前用户范围）保护密钥；它不能让一个已经用另一把公钥构建的管理器突然接受新密钥。

正式 Bundle 的 `usb-manifest.json` 必须声明：

```json
{
  "usbGuard": {
    "signing": {
      "policy": "SignedRequired",
      "keyId": "prod-2026-01",
      "publicKeySha256": "<32 字节 Ed25519 公钥原始字节的 SHA-256，小写 64 位十六进制>"
    }
  }
}
```

签名器在写入前同时比较 `policy`、`keyId` 和公钥原始字节摘要。缺少声明、声明为开发自动注册、KeyId 不同或公钥摘要不同，均 fail-closed。不会把私钥写入 Bundle、U 盘、命令行或日志，也不会为了实现“一键”而改成信任 U 盘自带公钥。

## 3. 本机密钥生命周期

1. 扫描和 Bundle 深度检查通过后，签名器扫描本机受保护密钥目录。
2. 只有一个可解密 DPAPI Blob 时自动复用；多个可用 Blob 时停止并提示清理签名机环境，避免无感选择错误密钥。
3. 没有任何 Blob 时，自动创建默认 KeyId 对应的 DPAPI Blob，并写入只含公钥信息的本机状态文件，绝不覆盖已有 Blob。
4. 自动创建的密钥仍必须先用于生成匹配的 `SignedRequired` 管理器/Bundle；如果当前 Bundle 不是该密钥构建，界面明确提示“签名环境与当前安装包不匹配”，不执行签名。

## 4. 实现边界

- CLI 和 GUI 继续共享 `run_with_args`，避免出现第二套签名算法。
- GUI 只隐藏技术参数；底层仍保留精确目标、物理介质重观察、原子写入、回读验签和本地报告。
- `usb-manifest.json` 的签名绑定元数据属于不可变 Bundle 内容，会被现有 Anchor/SHA256 完整性检查覆盖。
- 自动生成只发生在本机固定磁盘的 signer 目录，并通过 DPAPI 用户绑定；不能从 U 盘、网络盘或重解析路径读取密钥。

## 5. 验收矩阵

| 场景 | 预期 |
| --- | --- |
| 空 U 盘 | 扫描失败/无候选，签名按钮禁用，不创建 U 盘文件 |
| 普通错误目录 | 不被识别为候选，签名按钮禁用 |
| Bundle 缺文件、哈希错或含 `apps/Codex` | 深度检查失败，不签名 |
| 两个合格 Bundle | 停止，不让用户在 GUI 里挑一个 |
| 开发自动注册 Bundle | 显示“不是正式签名包”，不签名 |
| 正式 Bundle 与本机 KeyId/公钥摘要一致 | 一键签名，自动回读验签通过 |
| KeyId 或公钥摘要不一致 | 明确报错，不写 `usb-license.json` |
| 本机无 Blob | 自动生成 DPAPI Blob；若当前包不匹配，仍停止签名 |
| 已签名 Bundle | 拒绝覆盖 |
| 写入期间拔盘/目标变化 | 失败或结果未知，不提示成功 |
