# Codex U 盘绑定与本地看门狗开发文档

状态：P1 MVP 已落地（2026-08-31）。本文同时作为实现约束和现场验收清单；P2“开始菜单直接启动拦截”仍未启用。

## 1. 目标与边界

目标是在现有离线 Codex 安装器上增加“指定 U 盘才可用”的产品层能力：

1. 只有插入登记过的 U 盘，才能完成启动授权。
2. U 盘拔出后约 5 秒内，关闭本产品管理的 Codex、CCSwitch 及其子进程。
3. 将安装包复制到电脑、网络盘或另一块 U 盘后，不能获得有效授权。
4. 保持 Codex 原版 MSIX 运行方式，不修改 `WindowsApps` 内部文件、不注入 DLL。
5. 提供可见的状态、倒计时、日志、修复和完整卸载入口。

非目标：本方案不承诺防止专业逆向、调试器伪造设备信息或内核级对抗。离线客户端只能提高普通复制的成本；需要更强保护时必须增加在线授权服务。

| 同一批日志中的 `spawn-detached`、PID 和 Gateway 清理记录 | 启动器负责管理子进程；运行时和用户数据可落到 C 盘 |

### 2.2 尚未能从样本证实的部分

备份中的 `ranclaw\versions\1.5.9\resources\app.asar` 物理有效数据只有约 127 MB，而逻辑文件大小约 216 MB，后半部分已损坏/补零。因此无法从这份副本确定：

- 它使用的是卷序列号、USB 物理序列号、PNP ID 还是自定义授权值；

- 是否存在额外的签名、加密或服务端租约。

“5 秒后退出”和“复制后失效”是由目录结构、日志和运行模型支持的高可信推断，正式开发前应做一次现场黑盒验证。

## 3. 当前 Codex 版本的事实与缺口

当前项目目录为 `D:\AI\AGENT_U盘\codex-desktop-usb-installer`。

- `CodexDesktopSetup.exe` 从 U 盘读取并校验 `manifest.json` 与 `payload\OpenAI.Codex_x64.msix`。
- MSIX 安装成功后，Codex 本体进入 `C:\Program Files\WindowsApps\...`；U 盘不再是 Codex 二进制的运行位置。
- CCSwitch 被复制到 `%LOCALAPPDATA%\Programs\CodexSwitch`。
- 现有代码没有 U 盘硬件指纹、租约、常驻看门狗或拔盘退出逻辑。
- 用户可以从开始菜单直接打开已安装的 MSIX；仅保护 U 盘启动器不能覆盖这个入口。

P1 实现后的新增事实：

- `src-tauri/src/app/usb_guard.rs` 提供指纹、许可证、租约、5 秒状态机和 Windows 适配。
- 管理器启动时把自身复制为 `%LOCALAPPDATA%\CodexUsbGuard\CodexUsbGuard.exe`，以 `--codex-usb-guard` 无窗口运行；不注册隐蔽的系统服务或开机启动项。
- 首次从可移动盘启动且没有 `usb-license.json` 时自动生成未签名开发许可证；正式发行应在离线构建机按每只 U 盘预置签名许可证后再交付。
- 租约记录管理器、CCSwitch 以及管理器启动后新出现的 `Codex.exe`/`ChatGPT.exe` PID。退出采用“先优雅关闭、250 ms 后 PID 级强制关闭”。
- 卸载会先停止租约和看门狗，再清理 Codex/CCSwitch；CCSwitch 共享数据只有在 `.codex-usb-managed.json` 所有权标记存在时才会按用户选择清理。
- 前端离线主页增加 U 盘授权/看门狗状态卡，并每秒刷新状态和倒计时。

因此，安装器只能作为“授权入口”，不能单独承担运行期绑定。

## 4. 推荐总体架构

```text
U 盘 CodexDesktopSetup.exe
        │  校验清单、设备指纹、签名租约
        ▼
本机 CodexUsbGuard.exe（C 盘、用户级、可见且可卸载）
        │  每秒检查 U 盘，管理租约和进程树
        ├── Codex MSIX（WindowsApps）
        └── 本产品 CCSwitch（LocalAppData）
```

### 4.1 U 盘启动器

职责：

- 检测当前介质为可移动磁盘；
- 读取并验证签名的产品清单；
- 计算当前 U 盘指纹；
- 安装/修复 Codex、CCSwitch 和本地看门狗；
- 向看门狗发放一次启动租约，并传递受管理进程的包身份/PID；
- 不能在无有效租约时启动 Codex。

### 4.2 本地看门狗

必须复制到 C 盘。P1 使用用户级安装目录，但只在管理器运行期间启动，不创建隐蔽登录启动项；安装和卸载必须在 UI 中明确显示，不允许隐蔽驻留。

看门狗保存：

- 产品安装 ID；
- 受管理的 Codex 包身份；
- 本产品 CCSwitch 的绝对路径及安装标记；
- 当前租约状态、最后一次检测时间和诊断日志。

任何需要保护的秘密都应使用 Windows DPAPI 保护；不要把 API Key 写入 U 盘绑定状态。

### 4.3 进程管理

- P1 通过管理器启动前后 PID 差集登记 `Codex.exe`/`ChatGPT.exe`，并在 taskkill 前再次校验 PID 和镜像名；这覆盖管理器启动的进程，但还不是完整的 AppX 包身份拦截。
- CCSwitch 使用本产品安装目录、文件哈希和安装标记识别。
- 退出时先发送正常关闭请求，短时间无响应再强制关闭进程树。
- 只处理由本产品登记的进程，不能影响用户另外安装的官方 Codex 或其他 CCSwitch。

## 5. U 盘绑定方案

### 5.1 指纹组成

建议按稳定性组合：

```text
可移动磁盘类型
+ 卷序列号
+ 物理磁盘序列号或 PNP 设备实例 ID（可获得时）
+ U 盘授权文件哈希
+ 产品清单版本和签名
```

盘符只用于显示和临时访问，不能作为授权主键，因为同一 U 盘换电脑后可能由 `F:` 变成 `E:`。

对“无物理序列号”的低质量 U 盘，应在首次注册时明确提示绑定强度较低；重新格式化默认视为新设备，需要重新注册。

P1 当前落地字段为“可移动卷类型 + 卷序列号 + `manifest.json`/`usb-manifest.json` 锚点哈希 + 包内相对路径”。盘符只用于扫描和显示。尚未接入物理磁盘序列号/PNP ID，因此极少数克隆出相同卷序列号的设备仍需 P2/发行加固处理。

开发包的首次绑定是“无许可证则写入当前卷指纹”的自注册模式，适合本地联调，但无法阻止“在首次运行前把整个目录复制到另一块 U 盘后再首次启动”。要兑现严格的防复制承诺，发行流水线必须先读取目标 U 盘卷信息，生成并签名 `usb-license.json`，再把完整目录交付；发行构建应关闭无签名自注册。

### 5.2 签名清单

U 盘内建议包含：

```text
usb-license.json
manifest.json
manifest.sig
```

构建环境离线持有私钥；看门狗只内置公钥。签名内容至少覆盖产品 ID、允许的 Codex/CCSwitch 哈希、版本、设备绑定策略和协议版本。

`SHA256SUMS.txt` 只能发现传输损坏，不能作为信任根；因为攻击者可以同时替换文件和哈希清单，正式版本必须增加签名或服务端租约。

## 6. 拔盘检测与 5 秒策略

推荐使用单调时钟而不是“失败五次”作为最终条件：

1. 看门狗每 1 秒检查设备是否仍为同一物理 U 盘。
2. 首次失败显示“U 盘暂时断开”，开始倒计时。
3. 连续不可用达到 5 秒，先关闭 Codex 和 CCSwitch。
4. 关闭失败时再强制结束受管理的进程树。
5. 在 5 秒内重新枚举到同一设备则清除倒计时；盘符变化不应导致误杀。
6. U 盘重新插入后必须重新验证指纹和签名，不能仅凭路径恢复授权。

需要记录 `detectedAt`、`missingAt`、`terminatedAt` 和退出原因，方便现场验证“5 秒”是否满足。

## 7. 直接启动入口的处理

MSIX 会出现在开始菜单，因此第一版若要求“没有 U 盘绝对不可用”，看门狗需要在 Codex 已安装且产品处于绑定状态时监控对应的 Windows 包身份：

- 有有效租约：允许本产品实例运行；
- 无有效租约：拒绝或关闭该产品安装实例；
- 不能按通用进程名全局杀进程；
- 用户卸载绑定功能后，应删除监控和启动项。

这是比 U 盘启动器更高风险的功能，应在独立测试阶段确认不会误伤用户另装的 Codex。

## 8. 复制场景验收

| 场景 | 预期 |
| --- | --- |
| 从 U 盘直接运行 | 设备匹配，允许启动 |
| 复制到 `C:\` 后运行 | 无有效可移动设备，拒绝启动 |
| 复制到另一块 U 盘 | 物理指纹不匹配，拒绝启动 |
| 同一 U 盘换盘符 | 指纹一致，允许启动 |
| 重新格式化同一 U 盘 | 默认视为新设备，要求重新注册 |
| 拔盘后重新插入另一块盘 | 不得恢复旧租约 |
| 拔盘后 5 秒内重新枚举 | 不应误杀或应按产品策略恢复 |

## 9. UI/UX 要求

在现有离线主页增加一个“U 盘授权”状态卡：

- 已连接/未连接；
- 指纹匹配/不匹配；
- 看门狗运行状态；
- 最近一次检测时间；
- 拔盘倒计时；
- 查看日志、重新验证、修复看门狗、卸载全部组件。

缺少 U 盘时应显示清晰提示，不要静默退出。强制退出前给出 5 秒可见倒计时，便于用户理解行为。

## 10. 开发阶段

### P0：黑盒验证与协议冻结

- 用完整 OpenClaw U 盘做启动、拔出、换盘符、复制运行测试；
- 记录进程树、退出耗时和日志；
- 获取完整 `app.asar` 后再确认其指纹算法；
- 冻结 `usb-license` 和本地状态格式。

### P1：本地看门狗 MVP（已实现）

- 实现设备指纹读取、可选 Ed25519 签名许可证验证和 5 秒单调时钟倒计时；
- 只管理本产品租约中明确登记的 Codex/CCSwitch PID；
- 加入本地状态文件、UI 状态和卸载清理；
- 不拦截所有开始菜单启动，避免误伤其他 Codex 安装。

### P2：直接启动防绕过

- 识别 Codex AppX 包身份；
- 无租约时关闭本产品安装实例；
- 覆盖重启、睡眠唤醒、用户切换和盘符变化；
- 做误杀回归。

P2 的详细数据模型、Windows API、看门狗生命周期、测试矩阵和分阶段改造清单见
[`APPX-PROCESS-GUARD-DEVELOPMENT.md`](APPX-PROCESS-GUARD-DEVELOPMENT.md)。

### P3：发行加固

- 对看门狗和启动器做 Authenticode 签名；
- 保护本地状态和更新流程；
- 如商业风险需要，再引入在线租约/激活服务。

## 11. 验收标准

第一版必须同时满足（P1 自动化/代码覆盖的部分已标注）：

1. 未插入绑定 U 盘时，启动器明确显示 unsupported/mismatch 状态；真实实机仍需验收。
2. 已完成首次绑定的包复制到电脑或其他 U 盘无法通过设备验证；纯逻辑指纹和复制场景单测已覆盖。未签名开发包在首次绑定前的复制限制见 5.1，不能作为发行安全承诺。
3. 拔盘后从 `missingAt` 到受管理进程结束不超过 5 秒；状态机边界单测已覆盖，真实拔盘仍需验收。
4. 同一 U 盘换盘符不误判；相对路径/指纹单测已覆盖。
5. 只关闭本产品登记的进程；Rust 代码使用 PID + 镜像名二次校验。
6. 卸载能移除本地看门狗、Codex、CCSwitch；CCSwitch 所有权标记和共享数据保护已实现，真实锁文件场景仍需验收。
7. 断网不影响本地设备验证；P1 无在线租约依赖。

## 12. 安全与合规边界

- 当前离线包中的 Codex MSIX、商标、签名和再分发权不由本仓库许可证自动授予。
- 看门狗必须可见、可卸载、可记录日志，不应伪装成系统组件或隐藏行为。
- 不使用 DLL 注入、修改 WindowsApps 签名文件或全局粗暴 `taskkill`。
- 任何 API Key 只由用户输入并写入 CCSwitch 自己的安全配置；不进入 U 盘清单、Git 仓库或看门狗状态。
