# G38.2：Sub2API 预充值安全重试

## 1. 目的

本小版本只处理一个可恢复故障：U 盘已经完成签名和回读验证，但最后的预充值请求因网络、超时或本地清理异常没有得到确认。用户可以在签名工具中显式点击“重试预充值”，继续同一个后台操作。

G39.5 已补齐“建号后签名中断”的同机恢复边界：如果账号已经创建、用户 API Key 已生成，
签名器会把账号密码和用户 Key 放入当前 Windows 用户可解密的 DPAPI 加密恢复记录；下一次
对同一物理 Bundle 会续作原账号，不猜测编号、不重复建号。该记录不复制到 U 盘或发布目录，
签名回读成功后自动删除。跨 Windows 用户、跨机器或 Bundle 指纹不一致时仍 fail-closed。

## 2. 安全边界

本地待处理文件位于：

```text
%LOCALAPPDATA%\CodexUsbLicenseSigner\pending\USB-xxxx.json
```

文件只允许包含：

- 记录版本；
- U 盘资产编号；
- Sub2API 用户 ID；
- 预充值金额；
- 已签名许可证摘要；
- 由资产编号和许可证摘要推导的幂等键；
- 创建时间。

文件禁止包含管理员 API Key、用户 API Key、账号密码、登录邮箱和完整许可证内容。写入采用临时文件加原子替换，资产编号固定为 `USB-` 加数字，避免路径注入。

以上约束适用于预充值 pending 文件。注册恢复记录是另一类文件，位于
`%LOCALAPPDATA%\CodexUsbLicenseSigner\provisioning\`，使用 Windows DPAPI 加密，文件名只含
恢复标识摘要；其明文只在当前进程内存中存在，签名成功回读后删除。

## 3. 状态流程

```text
签名 + 回读通过
        │
        ├─ 金额为 0 / 已有账号绑定 → 不请求预充值
        │
        └─ 新账号且金额 > 0
              │
              ├─ 先保存 pending（稳定幂等键）
              ├─ 调用管理员余额接口
              ├─ 成功 → 清除 pending
              └─ 失败/超时 → 保留 pending，显示“重试预充值”
```

重试必须同时满足：当前 U 盘 Bundle 深度校验通过、许可证已签名、许可证存在账号绑定、待处理记录的用户 ID 与许可证绑定一致。重试只调用余额接口，不创建账号、不登录、不生成 API Key。

## 4. 幂等与异常语义

- 幂等键由 `USB asset ID + license digest` 稳定推导；首次调用和显式重试使用完全相同的键。
- 后端返回成功后，如果本地删除 pending 失败，文件会暂留；再次重试仍使用同一幂等键，不能改用新键。
- 管理员 Key 失效、用户不存在、金额被拒绝等错误会保留 pending，并在界面显示可复制的非敏感错误摘要。
- 不把“请求已发出”伪报成“余额已到账”；只有接口成功且待处理文件清理成功才显示完成。

## 5. 界面

签名器在原有注册/签名按钮旁提供“重试预充值”。没有已签名绑定或没有 pending 记录时按钮禁用。执行重试不再要求签名密码，因为它不修改 U 盘许可证；管理员 Key 仍从签名器本地配置读取。

## 6. 验收

- pending 文件可原子写入、读取、校验和清除；
- 待处理文件内容静态审计不含 password、admin key、api key；
- 本地 HTTP fixture 验证管理员 Key 只进入管理员请求、重试使用原幂等键；
- 预充值成功后 pending 被清除；失败时 pending 保留；
- 核心许可证、签名器单测、GUI 编译、Clippy 和 release build 全部通过；首轮独立审计提出的活动分组与摘要绑定问题已修复并回归，最终形式化独立审计代理未返回报告。
- 已完成一次明确授权的 404token 测试联调，验证了真实建号、用户 API Key、10 单位预充值与 pending 清除；未修改 Sub2API 服务端，也未把任何密钥或密码写入文档。

## 7. 未解决边界

当前既有 Sub2API API 没有“按用户安全读取已生成完整 API Key”的能力，因此恢复依赖本机
DPAPI 记录保存的原始密码/Key，仅限同一 Windows 用户和同一台机器。记录损坏、机器更换、
密码/Key 无法解密、统一分组变化或 Bundle 锚点变化时，工具必须停止并要求管理员人工核对；
不能跨机器复制恢复记录，也不能把它放入 U 盘。
