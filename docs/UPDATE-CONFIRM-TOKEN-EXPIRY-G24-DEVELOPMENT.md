# G24：更新确认阶段耗时与诊断改进开发文档

## 1. 目标

修复 Codex U 盘 payload 更新在「检查更新 → 确认安装」之间长时间重复读取本地 MSIX，导致用户看到“更新信息已过期”而无法开始下载的问题；同时让失败阶段和错误原因可从日志中定位。

本任务只改 Codex payload 更新通道，不改变 U 盘签名规则、安装到本机的独立流程、远端源选择策略或事务回滚协议。

## 2. 证据与边界

G24 报告记录了 v0.5.24-g28 在 774,918,112 字节的可移动介质上重复执行全量 SHA256，且在第二次远端 source resolve 后没有 download/commit/error 记录，最终显示“更新信息已过期”。

对照当前源码后需要修正报告中的一项推断：当前源码的 `payload_apply_codex` 没有调用 `arm_destructive`、`begin_operation` 或破坏性令牌校验，Codex 通道使用的是进程内更新锁和 U 盘授权复核。因此，不能把“令牌 TTL 已过期”作为当前源码的已证实根因；它可能是被测试的 g28 二进制与当前源码不同，或是前端/旧版本通用令牌路径的现象。

可以直接证实并必须修复的是：

1. `require_capability` 会全量读取 payload；
2. `verify_bundle_integrity` 又通过 `SHA256SUMS` 全量读取 payload；
3. 快照构造再次全量读取 payload；
4. 提交前还会重复执行同类校验。

这会把更新前置阶段放大为数 GB 的 U 盘读取，延长用户确认窗口，并且让真实失败点缺乏阶段日志。

## 3. 安全设计

### 3.1 允许复用的范围

只在同一次本地完整校验调用链内复用已经由 `SHA256SUMS` 校验得到的摘要：

- `verify_sha256_sums` 新增返回已验证文件摘要的内部变体；
- 快照从这次完整校验的摘要表构造，不再为 payload 单独再读一遍；
- 既有无摘要参数的函数和测试入口保持兼容。

不跨越“检查更新”与“用户确认安装”缓存 payload 摘要，也不把文件大小/mtime 当作安全等价物。

### 3.2 提交前仍做独立复核

apply 的初始阶段和真正替换 live payload 前的提交阶段都保留完整的能力检查与 `SHA256SUMS` 校验。提交阶段在移动旧 payload 前继续独立读取当前 payload 摘要并与 manifest 比对，避免为降低 I/O 而削弱 TOCTOU 防护。

预期结果是：

- check：从约 3 次 payload 全量读取降为 1 次；
- apply 初始复核：从约 3 次降为 1 次；
- commit 前复核：从约 4 次降为 2 次 payload 全量读取，保留 capability 元数据检查、完整清单校验和提交边界独立摘要复核。

## 4. 实现项

### 4.1 摘要表

- 新增 `verify_sha256_sums_with_digests`，返回规范化相对路径到 SHA256 的映射；
- 保留 `verify_sha256_sums` 包装函数，避免影响事务恢复、构建和现有单元测试；
- 新增 `verify_bundle_integrity_with_digests`。

### 4.2 快照构造

- 新增从已验证摘要表构造 `LocalBundleSnapshot` 的函数；
- root manifest、usb manifest、payload 使用已验证摘要；
- `SHA256SUMS.txt` 自身仍单独摘要（它不应列入自身校验清单）；
- 缺少必要摘要时立即报错，不静默降级为未校验。

### 4.3 更新流程

- check 使用一次能力检查 + 一次完整清单校验 + 摘要快照；
- apply 的本地前置校验复用该次清单校验摘要构造确认快照；
- commit 使用同样的内部摘要表构造最终快照，并保留替换前的独立 payload 摘要检查；
- 在能力检查、清单校验、快照比较、远端复核、下载、提交和失败收尾阶段写入明确日志。

### 4.4 错误可观测性

命令边界对 Codex apply 的错误统一记录 `stage=command`、错误码和错误文本；通道内部记录关键阶段开始/失败。日志不得记录令牌、签名材料、API key 或用户凭据。

若未来重新接入破坏性令牌，必须另行实现长任务续期或把令牌绑定到操作身份而非固定短 TTL；本任务不通过自动重试或放宽授权来掩盖状态变化。

## 5. 验收标准

### 代码

- 现有 Codex 通道测试全部通过；
- 新增测试证明摘要表可构造快照，缺少必要摘要会失败；
- 现有 SHA256 重复项、覆盖项、事务恢复测试继续通过；
- apply 失败日志包含阶段和错误，不出现“无日志失败”。

### 行为

- 未联网时仍能明确提示网络/源解析失败；
- U 盘、manifest、SHA256SUMS 或 payload 在确认后变化时仍拒绝提交；
- 正常更新仍下载、校验、Authenticode 校验、提交并可恢复；
- 不引入跨用户、跨会话的本地 hash 缓存。

### 已知不能仅靠本地单测证明的事项

- 真实 NTFS U 盘在不同 USB 速度下的墙钟耗时；
- 中国大陆网络下各镜像源的可达性；
- g28 二进制中报告的具体令牌 TTL，因为当前源码未将 Codex payload apply 接入该令牌路径。
