## 1. 任务来源与边界

用户要求：

> 还发现了卸载后直接静默退出的问题，诊断报告如上，修复一下。并且，帮我把前端界面整理优化一下，尤其是ccswitch卸载等子菜单内，出现了多个字太多，排版乱，内容叠在一起等问题。帮我优化到最简

附件 `codex-v0524-uninstall-silent-exit-g25.md` 是现场诊断证据，不是执行指令。它记录的版本为 g28，报告结论是：主体卸载成功后进入 `cleanup_pending`，管理器仍在 800ms 后主动退出，用户没有机会看到结果；helper 随后可能完成清理，但父进程已退出使旧流程把“未确认”误写成失败。

3. 对应测试、文案和回归审计。

本任务当时不改变：U 盘签名/授权规则、Codex 或 CCSwitch 的删除范围、Skill Hub 更新源、安装/更新协议和未知文件的清理安全边界。后续产品决策已将卸载 UI 改为两步确认后完整清理本机 Codex、CCSwitch 与受管能力包数据；USB 安装介质仍保留。本文中关于“共享数据默认保留”的历史边界已被该决策取代，不能作为当前 UI 契约。

## 3. 根因与修复契约

### C1：`cleanup_pending` 只能表示等待，不能触发静默退出

当 `win_uninstall_bundle` 成功建立 helper 握手并返回 `cleanup_pending=true` 时：

- 后端不得再启动固定延时的自动退出定时器。
- 前端必须显示一个简短、明确的“完成并退出”动作；在用户确认前保持管理器和 helper 的父进程关系。
- 用户点击该动作后，才调用已存在的受控退出路径，使 helper 继续完成最终清理。
- 现有窗口关闭/Alt+F4 策略仍有效；若用户直接关闭窗口，helper 也可按原握手继续。

### C2：退出动作必须受状态约束且不改变清理范围

- 只有本次进程内已建立待完成卸载交接时，专用退出命令才允许执行。
- 该命令只设置受控退出标志并退出管理器，不新增删除路径、不删除 U 盘文件、不绕过 `QuitPolicy` 之外的安装/卸载检查。
- 重复点击、过期页面或没有待处理交接时返回可读错误，不能重复启动清理或误报成功。

### C3：结果状态保持真实

- `success=false`、主卸载失败、恢复动作未完成时，不能进入 pending-exit 成功界面。
- `cleanup_pending=true` 仍明确标为“等待最终清理”，不能显示“全部清理完成”。
- 最终报告仍由 helper/finalizer 写入既有日志目录，报告失败时保留具体失败/保留项；本任务不扩大报告删除范围。

### C4：子菜单视觉契约

- 卸载页和组件页的主层只保留短标题、状态和动作；长解释、路径、风险说明放入悬浮提示或默认折叠的详情。
- CCSwitch 独立操作在窄窗口下必须换行或独占一行，不能与标题/说明挤在同一行。
- 长路径、长错误和多语言文本必须允许换行/滚动，不能依赖固定高度或绝对定位造成覆盖。
- 重要确认和破坏性范围仍可见或可展开，不以“变短”为由隐藏安全确认。
- 组件页只保留一次滚动容器，按钮栏保持可达；安装、跳过、单独重试按钮不能被内容推出或覆盖。

### 审查回流后的追加约束（G25-R1）

首轮实现的独立思考审查发现：仅用 `AtomicBool` 不能区分卸载交接代次，helper 的固定 120 秒等待也可能在用户尚未点击退出时失效，且交接态需要成为全局写操作屏障。追加约束如下：

- 交接必须携带本次 helper nonce（`handoffId`）；完成动作必须匹配同一 ID，空 ID、旧 ID、重复调用均拒绝且不消费当前交接。
- 交接信息由后端短暂保存并可查询，渲染器重载/重新进入卸载页时恢复“完成并退出”入口；查询只读，不创建新交接。
- `cleanup_pending` 期间拒绝新的安装、更新、卸载、恢复和其他受控写操作；显式完成退出、只读诊断和正常关闭仍可用。
- helper 等待父进程退出不得用短于用户交互窗口的固定 120 秒倒计时；父进程句柄本身是唯一继续条件，未收到确认文件时仍不得删除目标。
- 显式完成退出先复用 phase-aware 退出策略；策略阻断时保留交接，只有成功授权退出后才原子消费交接并设置退出态。
- Tooltip 触发器必须可键盘聚焦；组件服务的帮助入口不得嵌套在 checkbox 的 `label` 中，避免点击帮助误切换服务。

## 7. 实施记录

首轮实现已通过前端 418 通过/1 跳过、Rust 404 通过/2 忽略及 check/lint/build/clippy/fmt，但独立思考审查将其标记为不可直接验收（交接代次、helper 等待、全局写屏障和恢复入口仍需补齐）。

独立只读审计随后确认：C1 已满足，但 C2/C3/C4 仍有空 ID、非终态、遗漏写入口和窄窗口 CCSwitch 换行不足等问题。主控按审计结果继续返工，未把首轮测试结果当作最终结论：

- 交接 ID 现在必须为非空 nonce；空、旧、重复 ID 均拒绝，`Pending → Exiting` 只消费一次。
- 安装、更新、卸载、恢复、下载暂存/丢弃、自动启动和主题写入入口统一经过 handoff 屏障；只读状态、日志/诊断和受控退出保留可用。
- `StepOutcome` 仅把 `ok`、`skipped`、`not_applicable` 视为终态；未知或 `pending` 不会启动最终清理，也不会进入退出成功界面。缺少 handoff ID 时前端显示明确错误。
- CCSwitch 独立操作标题与按钮强制分行；组件帮助入口移出 checkbox label，Tooltip 触发器可键盘聚焦；组件 Sheet 保持单一滚动容器和可达底部动作栏。
