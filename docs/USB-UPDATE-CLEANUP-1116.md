# USB 更新残留回收（1116）

## 已确认的缺口

1. `portable.rs` 在 `prepare_portable_payload` 完成后才触发 `BeforeMoveOld`；管理器在该事件中创建安装事务。解压被结束进程/断电打断时，部分落盘的 UUID 目录没有事务记录。
2. 引擎把旧程序目录删除失败写为 warning，但 `ActiveInstallTx::succeed` 随后清除日志。下一次更新没有可重试的清理记录。payload MSIX 事务已有成功删除、失败回滚逻辑，本次保持不变。

## 最小修补

- 增加解压前事件和 `extracting` 状态，用既有本机 install-transactions 日志在首次写入 staging 前记录安装、payload、backup 路径。准备完成后才进入原 `prepared`/提交边界，不提前修改授权、策略或运行中的程序。
- 恢复 `extracting` 时只有旧安装状态未变且没有 backup 才删除本事务 staging；不把半成品继续安装。准备完成后的原交换/回滚判断保留。
- Windows portable 清理仅接受引擎实际生成的关联路径：同一父目录、`portable-UUID/payload`、`Codex.rollback-UUID`。复用路径安全检查；保留不匹配、访问失败或仍有歧义的材料。
- 完成状态先持久化；旧程序和本事务 work 目录清理成功后才移除日志。失败保持日志，下次恢复重试。旧程序只在新安装已完成的状态删除；回滚仍优先恢复旧程序。
- 更新 apply 已有授权和锁之后、下载之前，恢复当前安装路径的事务；直接安装/再次初始化在解压前做相同恢复。没有完成的恢复不再继续堆积新目录。
- 不新增目录扫描兜底、不删除无事务的历史同名目录，不修改用户 HOME、账号、模型、技能、媒体、CUA/IAB 或 MSIX 完整性机制。既有日志仍为本机存储；不扩展成跨机器事务同步协议。

## 验证与放行

- 状态和真实文件回归：解压开始前/部分解压/准备完成后中断，恢复后重装；旧目录被真实 Windows 文件共享锁阻止删除，保留 completed 日志，释放后恢复；新程序替换失败回滚；未知目录、用户文件保持不变。
- 在已验证身份的隔离 NTFS 7.43 GiB 卷（小于用户显示 7.49 GB）完整新装、连续两次真实 MSIX 更新部署，加入中断恢复和删除失败恢复；原 digest、Authenticode、metadata 流程保持。
- 运行相关事务、portable、更新通道和 Terra 回归；沿原发布流程编译和包级审计，对比 Terra 基线的能力包、helper、CCSwitch、原始 MSIX，确认既有修补保留。
- 用户已在本任务明确批准原流程所需 SHA/hash/checksum；不新增检查、不进行实际签名、登记、充值或付费调用。

## 设计审计

清理的实际消费者是下一次更新下载/解压所需的空间。清理以现有事务路径及状态为证据，不以年龄或模糊名字判废弃。失败保留恢复证据；不以删除旧程序回滚材料换取空间。未来上游体积增长仍受真实容量限制，不能承诺任意版本都能装进 7.49 GB。
