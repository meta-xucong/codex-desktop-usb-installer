# 媒体 MCP 预装失败：诊断与修复验收

日期：2026-10-14

## 目标

修复 USB 启动器的统一媒体 MCP 预装漏检。媒体 MCP 启用时，只有本机服务文件已部署、Codex `config.toml` 已注册并启用正确入口、服务本地协议自检通过后，安装才可以报告成功。失败必须保留可定位的阶段诊断，不得把“凭据已同步”当成“MCP 已接入”。

## 证据与根因

测试机报告提供了本机凭据文件存在、但 `bin` 与 `config.toml` 注册缺失的观察；报告不能单独证明中断发生在哪个安装步骤。

代码核查确认两处验收缺口：

1. `installer-pack/install-to-codex.ps1` 会把总体安装状态写成 `partial`，但脚本末尾仍正常退出；配置合并失败也被捕获并写入 readiness，而不是在媒体 MCP 已启用时阻止成功退出。
2. `src-tauri/src/app/capability_pack.rs` 在子进程退出 0 后只要求 readiness 中核心 Skills/Agents 与版本有效。它没有检查媒体 MCP 的文件、已注册配置或协议状态。随后许可证凭据同步可成功，造成“本机有凭据、MCP 未接入”的半成品。

因此，本修复不声称已还原测试机具体中断点；它关闭上述确定性的假成功路径，并为重试定位留下阶段状态。

## 范围

- 修改 `installer-pack/install-to-codex.ps1`：媒体启用时，对部署文件、健康检查、配置合并及最终注册做 fail-closed 校验；以安全阶段记录补充诊断。
- 修改 `src-tauri/src/app/capability_pack.rs`：媒体启用时，验证本机 MCP 文件、Codex 注册状态及协议 readiness；凭据同步失败不得降级为成功。
- 修复 `OfflineHome` 的首次安装调用：安装前只读取一次授权上游 `/v1/models`，复用“连接与扩展”的相同模型选择器，填入受支持的最新图片/Grok 模型；模型目录不含受支持模型时，不启用媒体 MCP，但继续安装其余能力，并明确告知用户。Seedance 因目录不提供账户路由 ID，不在首次安装中自动启用；若本机已有 Seedance 模型与路由 ID，且该模型仍在目录中，则保留该配置并继续启用。
- 自动安装将选出的非秘密模型 ID 写入用户环境，让普通 Codex 启动时 MCP 能读取；目录请求失败时读取本地非秘密模型槽位：只有当前签名 U 盘仍提供有效授权，且已有模型设置可用时，才保持 MCP 启用且不改槽位；否则只跳过媒体 MCP。目录成功后按可用模型更新或清理。签名 U 盘 API Key 仍由 DPAPI 凭据注入，不能持久化到用户环境、TOML、日志或 readiness。
- 增补与上述边界相邻的单元/集成测试。

不改媒体 provider/API 行为，不调用付费生图或视频接口，不改测试机，不清理现有工作区临时目录，不提交或推送。

## 验收

1. 已启用媒体 MCP 的健康安装可报告 `ready`，并能从 readiness 找到 `media_generation` 的服务版本、协议状态和注册状态。
2. 缺少 wrapper/server、健康检查失败、配置未注册/未启用、凭据写入失败时，安装返回失败并指出失败阶段；不允许核心 Skills/Agents 就绪覆盖媒体失败。
3. 无关 MCP 配置保留；不把 API Key 写进 TOML、诊断或 readiness。
4. 禁用媒体 MCP 时不要求媒体文件或媒体注册。
5. 默认首次安装必须在部署前读取模型目录并自动选择匹配模型；不可用/空目录不能阻断其余能力包安装，且不得报告媒体已可用。目录请求失败时只有在有效签名授权与已有配置同时存在时才保留媒体启用状态；否则关闭媒体 MCP。成功目录移除无效设置并保留目录仍有效的手动 Seedance 路由。不得使用硬编码过期模型作为回退。
6. 自动安装后验证选定模型 ID 对普通启动入口可见；媒体 API Key 不出现在用户环境、TOML、诊断或 readiness。
7. 使用合成 profile 与本地协议检查完成回归；模型目录 GET 可以实测，不调用真实生成 API。

## 修订记录

- 2026-10-14：独立审计发现 USB 首次自动安装路径启用了媒体 MCP，但模型字段全空；PowerShell 预检因此报错。修复范围扩展到同一调用链：首装先查目录并选择模型，同时确保模型 ID 被持久化供普通 Codex 启动读取；没有可用模型时仅跳过媒体 MCP，不阻断其余能力包。再审计补上目录失败时保留用户现有选择、仍有效的手动 Seedance 模型/路由组合，以及目录离线时维持已有 MCP 注册启用状态。
