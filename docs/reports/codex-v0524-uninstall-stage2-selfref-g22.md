# G22：卸载二阶段报告自引用故障归档

## 现场结论

旧版本在删除 App Manager 本地数据目录后，二阶段收尾仍尝试把最终报告写回
`%LOCALAPPDATA%\io.github.wangnov.codexappmanager\logs`。目录已经不存在时，Windows
弹出“位置不可用”，并返回 `E_FAIL`。Codex、CCSwitch 和能力包的本地清理可能已经完成，
失败点是报告回写和收尾状态判定，不应被误报成“所有卸载都失败”。

## 修复契约

- 最终报告固定写入 `%TEMP%\CodexAppManager\uninstall-reports`，该目录不属于任何删除目标。
- 进入二阶段前先捕获日志尾部；二阶段只读写独立临时报告目录。
- 报告包含 `phase`、`exitCode`、`retrySuggestion` 和具体失败条目。
- “打开日志”在产品目录不存在时回退到独立临时报告目录，不能复活已卸载的数据目录。
- 启动二阶段前对报告根目录和清理目标做规范化路径交叉检查。
- 静态 U 盘发行目录不携带 `usb-license.json`；签名工具只在用户复制完成的目标 U 盘上生成授权文件。

## 验收

Rust 卸载清理单元测试覆盖报告路径安全、finalizer 成功/失败状态、具体失败项和旧版桌面报告清理；
发行包验证还检查独立报告路径契约及静态包不含运行期授权文件。
