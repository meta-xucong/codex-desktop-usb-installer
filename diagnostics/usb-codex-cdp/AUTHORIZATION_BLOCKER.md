# Authorization blocker and scope

The feature-gated `codex-usb-cdp-diagnostic` launcher EXE has been compiled, but no diagnostic USB package was built or signed. The supported startup chain requires the running manager process to locate and validate its signed USB bundle and acquire a lease bound to its own PID. `bundle_root_for_executable` accepts an EXE directly in the bundle root or directly in `resources`; an EXE elsewhere is not found and startup becomes restricted. A new EXE placed in the bundle is subject to the root SHA ledger, where unlisted immutable files are rejected.

The normal manager startup creates a `UsbLease` with `owner_pid` and records the manager executable path in `managed_processes`. `validate_lease_observation` rejects another owner PID. The diagnostic target uses compile-time-distinct guard arguments, local directory, helper filename (`CodexUsbCdpGuard.exe` under `%LOCALAPPDATA%\CodexUsbCdpDiagnosticGuard`), Windows elevated-session mutex, Tauri identifier and manager data/log/cache roots, so diagnostic initialization does not stop or replace the formal helper or share its lease/status files/settings/provenance. The ordinary `codex-app-manager` binary rejects the diagnostic Cargo feature. The diagnostic manager also requires an explicit `CODEX_USB_CDP_DIAGNOSTIC_CODEX_HOME` value resolving to an existing absolute, non-symlink directory; no Codex profile is copied or created. It retains the same signed bundle, license, fingerprint, and PID-bound lease checks.

This is distinct from `authorize_usb_codex_launch`: that function checks the signed bundle and selected Codex target. It does not itself copy the guard helper. The helper copy is a later successful manager-initialization side effect.

A runnable test package still requires a separate USB bundle whose immutable hash ledger covers this EXE and a valid USB license signed over that bundle's anchor/fingerprint. The new `-UsbCdpDiagnostic` switch in `tools/build-installer.ps1` builds/stages the feature-gated manager; `build-oneclick-usb-layout.ps1 -InternalSigned` then constructs a static bundle and SHA ledger; the USB license signer must sign the finalized bundle on the intended removable volume. No signer vault/private key was read, and no license or credentials were created or changed. The package is therefore not ready to copy/run yet.

A separate process using an explicitly selected existing Codex profile permits Codex to write its normal startup state there. No live diagnostic instance was started.
